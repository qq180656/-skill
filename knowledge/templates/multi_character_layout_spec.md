# 多角色布局控制方案 (Multi-Character Layout Protocol) v1.0
# 补丁文件：补充 character_lock_protocol.md 的执行层控制
# 目的：解决 Agent 在多角色镜头中无法有效控制角色空间关系、避免角色融合或变脸的问题
# 解决问题：Agent 只能通过 Prompt 描述，难以在多角色场景中实现稳定的站位与角色独立性

# ============================================================
# 1. 问题诊断
# ============================================================
# 当前角色锁定协议（character_lock_protocol.md）的局限：
#   - 只解决了“个体形象”的锁定（通过四视图和 Prompt 描述）
#   - 缺乏对“多角色交互关系”的约束（角色 A 站左边，角色 B 站右边，且互不干涉）
#   - 在多角色镜头下，模型容易出现：角色特征混合（A 的脸穿了 B 的衣服）、角色身份模糊、或者角色在画面中重叠/融合。
#
# 解决方案：引入“空间占位符 (Spatial Placeholder)”与“角色/场景解耦引用”策略

# ============================================================
# 2. 布局控制策略 (Layout Control Strategies)
# ============================================================

# 策略 A: 角色解耦引用法 (Decoupled Reference) —— 适用于 2-3 人镜头
# 逻辑：通过 ImageList 的顺序排列与 Prompt 中的显式角色绑定，建立“身份-图像”强映射。
#
# ImageList 排列规范：[角色A_Sheet, 角色B_Sheet, 场景参考图]
# Prompt 编写规范：
#   - 禁止使用："@图片1和@图片2在一起，一个穿白衣服，一个穿蓝衣服" (描述太模糊，易融合)
#   - 必须使用："@图片1所示的[角色A名]位于画面[方位]，@图片2所示的[角色B名]位于画面[方位]，场景参考@图片3"
#   - 强制加入方位词：左侧/右侧/中间/前景/背景/画面1/3处。

# 策略 B: 空间占位锚定法 (Spatial Anchor) —— 适用于 复杂布局/多人场景
# 逻辑：在 Prompt 中先定义一个稳定的“构图底座”，再将角色填入。
#
# Prompt 构造模板：
#   1. [构图底座]：高角度俯拍/中景镜头，画面分为[左/右/中]三个视觉区域，[场景描述]。
#   2. [角色 A 填充]：在画面[方位]处，出现@图片1所示的[角色名]，其特征为[物理白描]。
#   3. [角色 B 填充]：在画面[方位]处，出现@图片2所示的[角色名]，其特征为[物理白描]。
#   4. [交互动作]：[角色A]正在[动作]，[角色B]正在[动作]，两人之间保持[距离]。

# ============================================================
# 3. 角色锁定卡 (Character Lock Card) 扩展
# ============================================================
# 在生成的角色锁定卡中，针对“多角色”场景，需新增【布局属性】字段：
#
# | 字段 | 内容 | 说明 |
# |------|------|------|
# | 典型站位 | 左侧/右侧/中心/前景 | 用于 Prompt 生成时的方位约束 |
# | 交互关系 | 对视/背对/并排/递东西 | 用于控制两个角色之间的相对动作 |
# | 视觉优先级 | 角色A（主）/ 角色B（配） | 决定模型在处理冲突时的权重分配 |

# ============================================================
# 4. 角色融合(Character Merging)的拦截与修复
# ============================================================
# 识别融合现象：ASR 或 视觉比对发现 角色 A 的特征出现在 角色 B 身上。
#
# 修复优先级：
#   1. [轻量级] 修改 Prompt：增加强隔离词。
#      - 错误："@图片1和@图片2正在说话"
#      - 正确："@图片1所示的[A名]站在左边，@图片2所示的[B名]站在右边，两人中间有[桌子/间距]隔开，互不重叠"
#   2. [重做级] 修改 ImageList：
#      - 如果模型无法区分，改用“单人+背景”模式。即：先生成角色 A 在场景中的镜头，再生成角色 B 在场景中的镜头，最后通过镜头切换或分屏处理。
#      - 这种做法属于“PLANNING 阶段的规避”，即在分镜设计阶段就避免设计“两个角色在同一空间产生物理接触”的镜头。

# ============================================================
# 5. 集成到 character_lock_protocol.md 的位置
# ============================================================
# 在 character_lock_protocol.md 的“多角色场景引用规则”章节下，
# 增加“布局控制规范”小节，并引用本文件中的“策略 A/B”与“融合修复逻辑”。
#
# 同时，在角色锁定卡模板中，强制要求增加【布局属性】字段，以便在 GENERATING 阶段的 Prompt 构造中调用。

# ============================================================
# 6. 能力边界声明
# ============================================================
# 1. 无法完全消除“物理重叠”：
#    - 当分镜设计要求“两人拥抱”时，即便使用本协议，由于模型本质是概率生成，仍有融合风险。
#    - 此时应通过 VERIFYING 阶段的“高风险人工审核”来解决，而非试图通过自动化手段闭环。
# 2. 不改变模型底层能力：
#    - 本协议是“Prompt 约束层”与“参考素材引用层”的工程化优化，不能让一个不支持多角色的模型突然变得支持。
#    - 对于 Seedance 等模型，优先采用“分时段/分镜头”的规避策略（即不让角色在同一个镜头内发生复杂的物理纠缠）。
