# 质量管控与修改协议

## 镜头修改协议（KEEP/CHANGE）

### 适用场景
用户要求重做/修改某个已生成的镜头时使用。

### 强制规则
- **先读后改**：重新生成前必须读取原始镜头的调用参数（_task_ids.jsonl），获取原始Prompt、参数等
- **KEEP/CHANGE分离**：明确区分保留部分和修改部分，保留部分逐字引用
- **对比确认**：修改完成后必须同时展示修改前后的视频，等用户确认后才重新合成

### KEEP/CHANGE模板
```
=== KEEP（原始意图，逐字保留） ===
场景：{从原始prompt复制}
角色：{从原始prompt复制}
运镜：{从原始prompt复制}
时长：{原始Duration}
参考图：{原始ImageList}
风格：{从原始prompt复制风格关键词}
质量约束：{从原始prompt复制}

=== CHANGE（用户修改请求） ===
修改内容：{用户原话}
影响范围：{情绪/动作/场景/光影/时长 等}
```

### 常见修改处理方式

| 修改类型 | KEEP范围 | CHANGE范围 | 处理要点 |
|----------|----------|------------|----------|
| 情绪/氛围调整 | 角色+场景+运镜+时长 | 光影+配色+BGM | 查风格速查表替换情绪参数 |
| 角色表演调整 | 场景+运镜+光影+时长 | 动作描述+表情 | 细化肢体动作和表情描写 |
| 场景替换 | 角色描述+运镜+风格+时长 | 场景描述+场景参考图 | 需新增场景参考图 |
| 运镜调整 | 角色+场景+风格+时长 | 运镜描述 | 从运镜指令表取标准写法 |
| 时长调整 | 角色+场景+运镜+风格 | Duration+动作密度 | 时长变长→增加动作；变短→精简 |

## 出片自检（交付前必做）

### 技术质量检查

| 症状 | 修复方向 |
|------|----------|
| 意外字幕/水印、肢体崩坏、模糊、时长不符 | 检查Prompt质量约束，修复后重新生成 |
| 角色不一致（面部变人、换装、中途变脸） | 检查参考图引用和角色锁定规则 |
| 风格漂移（画风不统一、配色/色温跳变） | 检查风格锚定是否生效 |
| 台词/旁白问题（音色不统一、台词截断/重复） | 检查台词口型句式和音色锚定引用 |
| 衔接处跳变、色温突变 | 使用首帧参考策略，统一光影描述 |

### 快速决策流程

```
自检不合格
  │
  ├─ 单个镜头问题 → 重新生成该镜头（参考KEEP/CHANGE协议）
  │
  ├─ 风格/一致性全局问题 → 检查创意文档和参考图是否统一
  │
  ├─ 音频问题 → 检查每段Prompt的音频指令是否一致
  │
  └─ 模型能力限制（肢体崩坏、运动不自然） → 降低动作密度/换景别/换风格规避
```

### 红线

- 内容审核失败立即停止，不改词、不删素材、不自行重试
- 禁止直接重试视频效果问题，必须先和用户确认修改方向
- 禁止生成水印或去除水印

### 参考视频验证检查项（补充）

> 以下检查项基于10条优质保险营销视频的共同特征提炼，详见 `reference_video_analysis.md` 第十一节。

- [ ] 前3秒是否有明确的冲突/悬念/提问信号
- [ ] 开场场景是否与产品类型匹配（重疾险→街头/办公室，意外险→街边，家庭险→厨房，医疗险→餐桌/医院，普惠保→病房）
- [ ] 产品讲解是否覆盖"门槛→保费→保障→赔付"4个核心信息层
- [ ] 台词是否口语化（无书面语、无条款直读、有语气词"啊/呢/嘛/吧"）
- [ ] 镜头是否以近景/特写为主，全景仅用于开场
- [ ] 讲解段是否有明确的信息递进层次（门槛→保费→保障→赔付→行动引导）
- [ ] 结尾是否有明确的行动引导
- [ ] 竖屏构图人物是否居中偏上
- [ ] 场景是否有生活道具增加真实感（烧烤架、火锅、茶杯、炒菜锅等）
- [ ] 对话是否有"提问→回答→引出产品"的自然过渡

## 关键帧辅助策略

> 以下策略仅在用户要求修改镜头时使用，不在首次生成时主动启用。

### 方式一：使用上一个镜头的尾帧作为当前镜头首帧
用于修改后发现空间衔接不佳的段。用 ffmpeg 截取尾帧：
```bash
ffmpeg -sseof -0.04 -i assets/{project}/shot_01.mp4 -frames:v 1 assets/{project}/shot_01_lastframe.png
```
然后在 Prompt 中使用：`@图片1作为该次视频前的画面状态，参考@图片2的角色形象，场景参考@图片3...`

### 方式二：生成当前镜头的关键帧图片
用生图工具生成当前镜头的关键画面构图（角色位置、姿态、场景布局），标记为中间产物，再作为首帧或画面参考传入视频生成。适用于需要精确控制空间关系或多人站位的镜头。

## 阶段确认门机制（v4.3新增）

> 本节从工业级短片制作管线中提炼，在保险视频的关键阶段增加确认门槛，避免方向跑偏后浪费生成成本。

### 确认门设置

| 阶段 | 确认门内容 | 确认前禁止 |
|------|----------|-----------|
| 创意文档完成后 | 故事理解、内容定位、角色定义、参考手法、制作规格 | 禁止进入元素资产生成 |
| 元素资产生成后 | 角色形象、场景方向、道具状态、音色方案 | 禁止进入分镜规划 |
| 分镜规划完成后 | 分镜列表、镜头调度、元素引用、音频层规划 | 禁止进入视频生成 |
| 镜头视频生成后 | 各镜头视频效果 | 禁止进入音频层/最终合成 |

### 确认门执行方式
每个确认门必须包含：
- 本步骤产物清单
- 用户需要审阅的关键点
- "确认继续"和"需要修改"两个选项
- 收到明确确认前不得调用下一阶段工具

### 权威来源与变更影响
用户提出修改后按顺序执行：
1. 分类变更（剧情/角色/场景/台词/资产/分镜/镜头/音频/剪辑）
2. 定位权威来源，先修改对应产物
3. 计算影响范围，沿依赖链定位受影响的部分
4. 最小范围更新，只重做实际受影响的部分
5. 展示四项清单：已更新、不受影响、仍需确认、需重生成

## 实体分离检查（v4.3新增）

> 本节确保旁白和画面角色严格分离，避免旁白被当成画面角色传参考图或要求口型匹配。

### 检查项

| 检查项 | 通过标准 |
|--------|---------|
| 旁白实体分类 | 旁白标记为narrator + off_screen，不作为画面角色 |
| 视觉资产 | off_screen旁白不生成角色图、不进入ImageList |
| 口型要求 | off_screen旁白不要求画面角色对口型 |
| 音频层归属 | 旁白只进入narration/audio_layers，不进入画面角色的key_element_audio |
| 分镜记录 | 每个镜头的visible_entities和audio_entities分开记录 |

### 红线
- 禁止把旁白写进画面角色的口型描述
- 禁止把off_screen旁白放进ImageList
- 禁止把旁白声音和画面角色声音混为同一个实体

## 音频Preflight硬阻塞（v4.3新增）

> 本节确保音色锚点时长在视频生成前已校验合格。

### 校验时机
1. **音色锚点生成后立即校验**：每条voice reference生成后当场读取actual_duration
2. **视频生成前硬阻塞**：调用视频生成前逐条校验AudioList

### 校验规则

| 状态 | 条件 | 处置 |
|------|------|------|
| checked_pass | actual_duration ≥ 3s 且 ≤ 镜头Duration | 可用于视频生成 |
| checked_fail | < 3s / 格式异常 / 不可解码 | 重新生成合格锚点 |
| unchecked | 未读取到duration | 阻塞，禁止发起视频生成 |

### 失败处置
- 优先重新生成合格音色锚点（选更长台词或加停顿）
- 禁止清空AudioList绕过阻塞
- 禁止修改视频Duration适配不合格音频
- 连续3次仍不合格时暂停，向用户报告

## 批量裂变交付检查（v4.3新增）

> 本节适用于使用批量裂变流程产出多个版本时的质检。详见 `batch_fission_playbook.md`。

### 版本对照表检查
- [ ] 每个成功版本是否都有独立成片
- [ ] 版本对照表是否逐版本说明了裂变维度取值、保留项、改变项
- [ ] 共享片段是否标注了哪些版本复用
- [ ] 失败版本是否明确列出失败环节

### 共享片段一致性检查
- [ ] 共享片段的route、时长、参考视频范围是否确实一致
- [ ] 共享片段是否只生成了一次
- [ ] 各版本引用共享片段时是否正确承接

### 裂变母版合规检查
- [ ] 所有版本的产品名、警示语是否与母版一致
- [ ] 所有版本的合规要素是否通过校验
- [ ] 不同版本的卖点侧重是否都基于母版产品信息，无虚构
```
@图片1作为该次视频前的画面状态，@图片2作为后半段画面参考，
参考@图片3的角色形象，场景参考@图片4...
```

## 衔接链重截判定

被修改的段若属于衔接链的前置段（storyboard中标记 `⇐NN` 的后段依赖前段尾帧起手），重生成后必须重截其尾帧、重生依赖它起手的后续段；不在衔接链上则只重生本段。

## 工业级质检门禁体系（v4.4新增）

> 从全球顶牛创意广告导演的G0-G4门禁协议和CineForge的三大死症预检、淘金制审片、反AI自检中提炼，建立覆盖"提示词→资产→生成→成片"全链路的门禁系统。

### G0-G4门禁协议

每个阶段必须通过对应门禁，才能进入下一阶段。门禁不过，回炉本阶段，不进下阶段。

| 门禁 | 阶段 | 检查项 | 不过处理 |
|------|------|--------|---------|
| G0 | 定档 | 题材/时长/画幅/风格/受众明确；Logline写了；弧光三格写了 | 补齐再走 |
| G1 | 剧本/创意 | 节拍表有钩子拍（前3秒最强一帧）；翻盘道具在前2-4拍埋过；产品角色已定义 | 回炉剧本 |
| G2 | 资产/定妆 | 凡跨镜复用的角色/场景/道具都有定妆要素和禁令；@命名字典完整；分镜-资产匹配清单就绪 | 回炉资产 |
| G3 | 分镜/提示词 | 三致死症预检逐镜过（见下）；14区块每段完整；AU微表情注入；动作闭环四拍；对方存在证据 | 回炉提示词 |
| G4 | 成片/装配 | 淘金制完成；帧墙审片逐镜判定；ASR逐字校验通过；合规五查通过 | 废弃不合格段，补抽 |

### G3三大死症预检（逐镜过）

| 死症 | 检测方法 | 不合格处理 |
|------|---------|-----------|
| 贴片死 | 这一条生成里是不是只有一个长镜头？ | 改多镜切镜，让模型自己剪；每2-3秒一个动作点 |
| 慢死 | 提示词里有没有慢词（缓缓/缓慢/慢镜头/升格）？有没有"每2-3秒一个动作点"？有没有写明"正常速度"？ | 删除慢词，加动作点，标注正常速度 |
| 漂移死 | 这镜的提示词有没有复述定妆要素+禁令？参考图是不是只用了资产级定妆图？ | 补定妆要素+禁令到B13区块；参考槽只放资产级定妆图 |

### 淘金制审片

不判整条过/废。满意的秒数裁进金矿库，问题段补抽。

**审片流程**：
1. 逐镜抽帧拼评审墙
2. 逐条写判定：过 / 裁尾 / 废+原因
3. 不合格先杀在装配前
4. 废片留档标原因，不默默删

**判定标准**：
- 过：能说出这条哪个瞬间出色
- 裁尾：前段好，尾段松，裁掉尾段用
- 废：答不上"这条哪个瞬间出色"

答不上"这条哪个瞬间出色"就继续抽。合格不等于满意。

### 帧墙审片

逐镜抽帧拼成评审墙，逐条写判定：

| 判定 | 含义 | 后续动作 |
|------|------|---------|
| PASS | 画面质量达标，叙事意图到位 | 进入装配库 |
| TRIM | 画面前段好但尾段松散 | 裁掉尾段保留好部分 |
| FAIL | 漂移/穿帮/违规 | 标原因废弃，补抽重生成 |

帧墙审片必须在实际抽帧后进行，不能只看视频播放效果。抽帧能看到播放时一扫而过的穿帮帧。

### 停线上报机制

发现以下污染/漂移，第一次就停线，不许"先凑合用"：
- 角色脸变了（跨镜面部不一致）
- 场景变了（同一场景不同段视觉不连续）
- 核心物件错了（保单/药品/道具形态不一致）
- ASR将保障描述中的"意外"误识别为"故意"（改变产品核心属性的致命错误）

### 反AI自检四项

交付前逐项过：

| 检查项 | 典型症状 | 修复方向 |
|--------|---------|---------|
| 像CG吗？ | 皮肤玻璃感/全画面锐利/粒子滥用 | 加胶片颗粒/降低锐度/删粒子描述 |
| 像广告吗？ | 人物摆拍看镜头/产品式打光/无人感空镜 | 加生活痕迹/人物不看镜头/环境光替代产品光 |
| 像电视剧吗？ | 信息说尽/平光正反打/居中排队构图 | 减少信息密度/加侧光/偏心构图 |
| 像参考图翻版吗？ | 构图配色同时像同一张参考 | 只抽参考的一个维度，其余原创 |

### "三个瞬间"验收

**G4最终验收门**：能一句话说出这条片"最出色的三个瞬间"吗？
- 说不出来→还没熔好，继续抽
- 说得出来→可以交付

### 装配纪律

1. 拼接必须重编码，不直接拼接原始流
2. 音轨逐段转wav按实测段界对齐
3. 有人声的素材原生音轨全静默（同步声锁）
4. BGM后期添加，不在生成阶段内嵌
5. 字幕后期硬压，不靠模型生成

## 量化评分与修改优先级（v4.4新增）

> 从影视编剧技能的量化评分表和修改优先级规则中提炼，为保险视频提供结构化的质量评估和修改排序工具。

### 保险视频量化评分表（30秒短视频版）

使用时机：创意方案完成后、分镜规划前；或成片交付前的二次审计。

每个维度0-10分，分数后必须跟一句理由。

| 维度 | 评分依据 | 10分标准 |
|------|---------|---------|
| 开场钩子 | 前3秒是否抓人 | 第一个画面有悬念或冲击，拿掉开场作品明显变弱 |
| 核心戏剧动作 | 目标+阻碍是否清晰 | 3秒内能说出主角想要什么、什么挡着 |
| 产品角色定义 | 保险产品是否真实参与转折 | 产品是关键证物/破局工具/关系证物，不是结尾展示 |
| 场景因果 | 每段是否由上一段推出 | 全链"因为"型连接，零"然后"型 |
| 价值转变 | 每段是否有价值状态变化 | 每段都有明确的价值对变化 |
| 人物主动性 | 主角是否在做选择 | 主角的行动改变故事走向，不是被设定推着走 |
| 台词/旁白克制 | 有没有解释设定 | 用动作和物件传递信息，台词只露冰山一角 |
| 结尾余韵 | 是否有回味 | 能截最后一帧当封面，且看完有余味 |
| 合规安全 | 是否触碰保险法/广告法红线 | 零绝对化用语、零编造疗效、警示语到位 |
| 视觉可拍性 | 描述是否都可拍可录 | 零心理描写、零括号暗示、零解释性台词 |

**整体判断**：总分90+可进入分镜；70-89需要修改主要问题后重评；70以下回炉创意方案。

### 修改优先级规则

发现多个问题时，按以下顺序逐一修改，不一次性大改：

| 优先级 | 问题 | 修改方向 |
|--------|------|---------|
| P1 | 因果断裂（场景之间没有"因为"关系） | 重排场景顺序或补建因果链 |
| P2 | 主角没有主动选择（被事件推着走） | 给主角加一个决定性动作 |
| P3 | 没有价值转变的场景 | 删除或合并到相邻场景 |
| P4 | 开场不抓人 | 重写第1拍，用最强一帧砸脸 |
| P5 | 结尾没有钩子或余味 | 重写末拍，留一个有余味的画面 |
| P6 | 台词解释设定 | 删台词，用动作/物件替代 |
| P7 | 节奏过满或过拖 | 重新配平节拍表时长占比 |

分数低但不影响主线的项目，放到后面改。优先改结构性问题，再改表面问题。

### 窄问题原则

修改时不知道方向，问一个窄问题而非发散多个版本：

- 错误："这场不好，我给你三个版本选"
- 正确："这场里，妈妈是想保护孩子还是不想让孩子知道？"

窄问题帮创作者做选择，多版本让创作者失去判断。
