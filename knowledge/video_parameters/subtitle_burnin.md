# 字幕烧录流水线规范

<!-- v4.1 | 2026-09-15 -->

## 核心原则

字幕文本用**客户原稿**（不用ASR识别文字），时间轴用**ASR逐字稿**（`字幕/{名称}_words.json`，ASR words 直出，见 `asr_processing.md` 第10.5章）。

一步解决三个问题：
- 错字（ASR识别错误，如"先进"→"新晋"）
- 产品名不规范（缺符号/括号）
- 断句切数字（机械断行破坏产品名和金额）

## 流水线总览

```
客户原稿台词（正确文本）
        │
        ▼
  ┌─ Step 1: LLM断句 ──────────────────────────────┐
  │  输入: 原稿全文                                  │
  │  规则: ≤14字软上限 / ≤18字硬上限                 │
  │       产品名 = 不可分割token，单独成行            │
  │       不切产品名、不切数字金额                    │
  │  输出: 断句后的文本行列表                         │
  └──────────────────────────────────────────────────┘
        │
        ▼
  ┌─ Step 2: 全局词指针对齐 ─────────────────────────┐
  │  输入: 断句后文本行 + ASR逐字稿                   │
  │  算法: difflib.SequenceMatcher 编辑距离对齐       │
  │       匹配上的字 → 取ASR时间戳                    │
  │       匹配不上的字 → 前后邻居线性插值              │
  │  质量门禁: 对齐率 < 85% → 停止烧录，输出报告       │
  │  输出: 原文对齐SRT + 偏移报告                     │
  └──────────────────────────────────────────────────┘
        │
        ▼
  ┌─ Step 3: 产品名高亮校验 ─────────────────────────┐
  │  输入: 原文对齐SRT + 产品名标记表                 │
  │  校验: 产品名首字时间偏差 > 0.2秒 → 标预警        │
  │  输出: 带高亮标记的SRT + 预警报告                  │
  └──────────────────────────────────────────────────┘
        │
        ▼
  ┌─ Step 4: 合并ASS ────────────────────────────────┐
  │  口播字幕: 白色，产品名黄色，普通文本白色          │
  │  警示语: 灰色，全程底部常驻（0秒到视频结束）       │
  │  警示语: 固定文本，不跟ASR时间轴                   │
  │  输出: .ass字幕文件                               │
  └──────────────────────────────────────────────────┘
        │
        ▼
  ┌─ Step 5: ffmpeg烧录 → 校验 → 交付 ───────────────┐
  │  烧录: ffmpeg将ASS硬烧入视频                      │
  │  校验: 检查输出视频时长/分辨率/字幕可见性          │
  │  交付: 最终视频文件                                │
  └──────────────────────────────────────────────────┘
```

## Step 1: LLM断句

### 输入
客户原稿全文（纯文本，含标点）

### 占位符保护断句法（防LLM切断产品名/改数字）

LLM 会无视"不要切开"的指令——实测 `Doubao-Seed-2.0-mini` 把"好医保·中老年长期医疗（2026版）"切成两行、把"100%"改写成"百分百"。

**解法**：断句前把不可分割 token 替换成占位符（如 `__TK0__`），LLM 看到占位符不知道怎么切就会保持原样。断句后再把占位符还原回真实文本。

```python
# 断句前
protected = text.replace("好医保·中老年长期医疗（2026版）", "__TK0__")
# 发给LLM断句
result = llm_segment(protected)
# 断句后还原
for line in result:
    line = line.replace("__TK0__", "好医保·中老年长期医疗（2026版）")
```

### 断句后校验（拼回原文，防LLM改字/增删）

LLM 断句时可能偷偷改字（100%→百分百、先进→先近）或漏字。断句后必须校验：

```
joined = 去标点("".join(断句结果所有行))
expected = 去标点(原文)
if joined != expected:
    重试（最多3次），全失败 → WAITING_USER
```

校验不过的不允许继续流水线。

### 断句规则

| 规则 | 说明 |
|------|------|
| 单行软上限 | 14字（尽量不超过） |
| 单行硬上限 | 18字（绝对不超过） |
| 产品名保护 | 产品名作为不可分割token，单独成行，即使17字也不切 |
| 数字保护 | 金额、百分比、年份等数字不与前后的字断开 |
| 标点优先 | 优先在逗号、句号、顿号处断句 |
| 语义完整 | 不在主语和谓语之间断句 |
| 双行规则 | 一条SRT条目最多两行，两行合计不超过28字 |

### 产品名token识别

产品名在断句前由人工标注或正则预匹配，标记为不可分割token。示例：

- 可分割文本: `你让我上哪给你弄这么多钱`
- **不可分割token**: `好医保·中老年长期医疗（2026版）`
- 可分割文本: `之前让你给爸投保你没投`

断句时遇到不可分割token，将其作为整体分配到独立行，不再拆分。

### 输出

断句后的文本行列表，每行附带标记：`normal` 或 `product_name`

示例：
```json
[
  {"text": "你让我上哪给你弄这么多钱", "type": "normal"},
  {"text": "之前让你给爸投保", "type": "normal"},
  {"text": "好医保·中老年长期医疗（2026版）", "type": "product_name"},
  {"text": "你没投", "type": "normal"}
]
```

## Step 2: 全局词指针对齐

### 输入
- 断句后的文本行列表（Step 1输出）
- ASR逐字稿：`字幕/{名称}_words.json`，格式 `[{"text":"字","start":0.32,"end":0.36}, ...]`（单位秒，3位小数；ASR words 直出、每字一条、不经LLM，见 `asr_processing.md` 第10.5章）
  - 同目录另有 `{名称}_逐字稿.srt`（每字一条SRT，人看/播放器加载用）；**程序一律读 JSON**

### 对齐前预处理：ASR 多字 token 展开（防字幕延迟）

火山ASR逐字稿里，数字/英文常被识别成**多字token**（如 `15.08` 是1个token、`百分之百` 是4字但对应原文 `100%` 3字符）。如果不展开，原文多字只能匹配ASR的1个token，剩余字全变插值→后续时间戳整体偏移→**字幕延迟**。这是实测踩过的坑。

**展开规则**（对齐前在ASR侧执行）：

| ASR token | 展开为 | 时间分配 |
|-----------|--------|---------|
| `15.08`（多字数字） | `1` `5` `.` `0` `8` | 等分原token时间 |
| `400`（多字数字） | `4` `0` `0` | 等分 |
| `百分之百` | `1` `0` `0` `%` | 中文数字→阿拉伯，等分 |
| `四百万` | `4` `0` `0` `万` | 等分 |
| 单字token | 不变 | 不变 |

展开后ASR字数增加→编辑距离匹配率显著提高→插值字减少→字幕不再延迟。

### 对齐算法

使用 `difflib.SequenceMatcher` 对"原文去标点连续文本"和"**展开后的**ASR去标点连续文本"做编辑距离对齐。

### 时间戳分配规则

| 情况 | 处理方式 |
|------|---------|
| 原稿字匹配上ASR字 | 取ASR该字的 start/end 时间戳 |
| 原稿字在ASR中漏识别 | 用前后已匹配字的时间戳**局部窗口**线性插值（前后5个已匹配字的平均时长，不用全局平均） |
| ASR多识别了字（原稿没有） | 跳过，不影响原稿时间轴 |
| 连续多个原稿字都漏识别 | 取最近的前后已匹配边界，均匀分配 |

### 插值公式

对于漏识别的字 `original[i]`，找到前一个匹配上的字 `prev`（位置 p，时间 t_p）和后一个匹配上的字 `next`（位置 n，时间 t_n）：

```
t_i = t_p + (t_n - t_p) * (i - p) / (n - p)
```

每个字的持续时间取**局部窗口平均**（前后5个已匹配字的 end-start 均值），不用全局平均（全局平均会让远距离插值漂移累积）。

### 质量门禁

```
对齐率 = 匹配上的字数 / 原稿总字数（去标点）

对齐率 >= 95% → PASS
对齐率 85%-95% → WARN（烧录但标记质检）
对齐率 < 85%  → STOP（停止烧录，输出报告，标记"需人工介入"）
```

### 偏移报告

每条视频输出 `_对齐报告.json`：

```json
{
  "video": "xxx.mp4",
  "orig_chars": 320,
  "asr_chars": 316,
  "matched": 308,
  "interpolated": 12,
  "align_rate": 0.9625,
  "status": "PASS",
  "mismatches": [
    {"pos": 45, "orig": "进", "asr": "晋", "type": "replace"},
    {"pos": 120, "orig": "息", "asr": null, "type": "asr_miss"}
  ]
}
```

### 输出
- 原文对齐SRT（字幕文字为原稿，时间轴来自ASR）
- 偏移报告（JSON）

## Step 3: 产品名高亮校验

### 输入
- 原文对齐SRT（Step 2输出）
- 产品名标记表（Step 1中断句标记的 `product_name` 行）

### 校验逻辑

对每个标记为 `product_name` 的SRT条目：

1. 取产品名首字在原稿中的序号 `i`
2. 从Step 2的偏移报告中取该字的匹配状态和时间戳
3. 如果该字状态为 `interpolated`（插值生成，非真实ASR匹配），时间戳不可信
4. 如果该字状态为 `matched`，但与ASR中相邻字的间隔异常（>0.5秒），标预警

### 预警规则

| 条件 | 级别 | 处理 |
|------|------|------|
| 产品名首字为插值 | WARNING | 时间轴可能不准，建议人工核对 |
| 产品名首字时间偏差 > 0.2秒 | WARNING | 高亮起止可能不同步 |
| 产品名末字时间偏差 > 0.2秒 | WARNING | 高亮结束可能提前/延后 |
| 产品名内有连续≥3个插值字 | ERROR | 产品名整段时间轴不可信 |

### 输出
- 带高亮标记的SRT（产品名行附带 `highlight:product` 标记）
- 预警报告

## Step 4: 合并ASS

### ASS样式定义

```
口播字幕（普通文本）:
  Font: 思源黑体 / Noto Sans SC / Microsoft YaHei（回退链）
  Size: 50pt@720p（等效75pt@1080p）
  Color: 白色 #FFFFFF
  Outline: 黑色描边 3px
  Position: 底部居中，画面下方1/4处（MarginV≈320@1280）

口播字幕（产品名高亮）:
  同上，但 Color: 品牌黄 #FFD700
  加粗

警示语（底部常驻）:
  Font: 同上回退链
  Size: 18pt@720p（等效27pt@1080p）
  Color: 浅灰 #CCCCCC
  Outline: 黑色描边 1px
  Position: 最底部居中，MarginV≈10
  Duration: 0秒到视频结束全程显示
  内容: 固定文本，不跟ASR时间轴
```

### ASS事件结构

```
[Events]
; 口播字幕（Layer 1，上层）
Dialogue: 1,start,end,Oral,,0,0,0,,{口播文本}
Dialogue: 1,start,end,Product,,0,0,0,,{产品名文本}

; 警示语（Layer 2，下层，全程常驻）
Dialogue: 2,0:00:00.00,video_end,Warn,,0,0,0,,{固定警示语文本}
```

### 产品名高亮实现

产品名行使用独立的ASS样式（`Product`，黄色加粗），与普通口播文本（`Oral`，白色）分开写入。

### 警示语规则
- **全程常驻**：从视频第0秒到最后一帧
- **固定文本**：不依赖ASR时间轴
- **灰色小字**：视觉上不抢口播字幕
- 内容按产品从合规文档取（每个产品的投放注意事项中的「压底文案」章节）

## Step 5: ffmpeg烧录 → 校验 → 交付

### 烧录命令

```bash
ffmpeg -i input.mp4 \
  -vf "ass=subtitle.ass" \
  -c:v libx264 -crf 18 -preset slow -pix_fmt yuv420p \
  -c:a copy \
  output_burned.mp4
```

关键参数：
- **`-c:a copy`**：音频不重编码（避免音质损失/音画不同步）
- **`-crf 18`**：视觉无损
- **ASS文件编码**：UTF-8 with BOM（libass需要）
- **Windows路径转义**：`C\:/path/to/sub.ass`

### 校验项

| 校验项 | 方法 | 通过条件 |
|--------|------|---------|
| 输出视频时长 | ffprobe | 与输入视频时长差异 < 0.5秒 |
| 输出视频分辨率 | ffprobe | 与输入视频分辨率一致 |
| 音频流存在 | ffprobe | 有音频流 |
| 字幕可见性 | 抽首/中/尾3帧 | ≥2帧底部区域有字幕像素 |
| 警示语可见性 | 抽帧检查 | 最底部有灰色文字 |
| 产品名高亮 | 在产品名时间段抽帧 | 有黄色文字 |
| 文件增幅 | 对比文件大小 | ≤15% |

### 交付物（每条视频）

| 文件 | 说明 |
|------|------|
| `{名称}_burned.mp4` | 烧录字幕后的最终视频 |
| `{名称}_原文字幕.srt` | 原文对齐SRT（可复用） |
| `{名称}_逐字稿.srt` | ASR词级逐字稿·人看版（每字一条，存档/播放器可加载） |
| `{名称}_words.json` | ASR词级逐字稿·程序版（Step 2 对齐读这份，**时间轴唯一源头**） |
| `{名称}_对齐报告.json` | 对齐率+错配明细 |
| `{名称}.ass` | ASS字幕源文件（可复用样式） |
| `{名称}.mp4` | 无字幕原版（**必须保留**） |

字幕类文件（`_原文字幕.srt` / `_逐字稿.srt` / `_words.json` / `_对齐报告.json`）统一存 **`{项目}/{日期}/字幕/`**，与口播字幕SRT同目录（不另建 `逐字稿/` 子目录）。逐字稿由 `asr_processing.md` 第10.5章 产出，本流程只读不改。

命名：烧录版加 `_burned`；多平台 `_burned_dy` / `_burned_wx`。

## 异常处理

| 异常情况 | 处理 |
|---------|------|
| 对齐率 < 85% | STOP，不烧录，输出偏移报告，标记 MANUAL_REVIEW |
| 对齐率 85%-95% | WARN，烧录但标记质检 |
| 产品名首字为插值且偏差>0.2秒 | 继续烧录，预警报告标记 |
| 产品名内连续≥3个插值字 | ERROR，产品名时间轴不可信 |
| LLM断句失败 | 换key重试3轮 → 全失败 WAITING_USER |
| ASR逐字稿为空 | STOP，报错（`_words.json` 缺失或为空数组，无时间轴可用） |
| 原稿为空 | STOP，报错 |
| ffmpeg烧录失败 | 重试1次 → 仍失败输出错误日志 |

## 红线

1. 禁止烧录后删除原始无字幕 mp4 和独立 SRT（双版本交付是硬要求）
2. 禁止字幕进画面上方1/3（人物面部核心区）
3. 禁止警示语字号大于口播（层级倒置）
4. 禁止烧录时修改字幕文字（要改→回 Step 1 改原稿断句→重新对齐烧录）
5. 禁止用 SRT 直接烧多层（必须转 ASS）
6. 禁止重编码音频（必须 copy）
7. 禁止跳过烧录后校验直接交付
8. 禁止本地机械切字生成字幕（必须 LLM语义断句 + ASR词时间戳对齐）
9. 禁止用 ASR 识别的文字做字幕文本（必须用客户原稿）
10. 禁止绕过逐字稿另取一份 ASR 结果做时间轴——时间轴只认 `字幕/{名称}_words.json`（逐字稿是唯一源头，口播字幕SRT 同样由它派生）

## 平台适配

| 平台 | 差异 | 适配 |
|------|------|------|
| 抖音/快手 | 避开底部交互栏 | 口播 MarginV 上移约20% |
| 微信视频号 | 安全区更小 | 口播字号可缩小约80% |
| 其他 | 默认 | 不改 |

多平台投放分别烧录，命名 `_burned_dy` / `_burned_wx`。
