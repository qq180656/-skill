# 第二层：视频生成 - 参数表

> **平台适配**：模型名/时长/分辨率/素材上限以运行时 `list_capabilities` 返回为准，本表数值为保险项目经验默认值。Key管理已替换为积分管理，详见 `core/platform_adapter.md`。

## 核心执行逻辑

### 模型单段时长上限

| 模型 | 单段时长范围 | 说明 |
|------|-------------|------|
| Seedance 2.5 | **4-30秒**（按文案字数动态选，5s步进） | 平台实际支持下限4s；extend模式多段拼接 |
| 其他模型 | 以 `list_capabilities` 返回为准 | 不硬编码模型名 |

### 单段时长动态选择（重要，不要固定30s）

每段视频时长按该段台词字数计算，**台词填满、留2秒缓冲**：

```
该段台词秒数 = 该段字数 ÷ 语速下限(字/秒)
该段视频时长 = 台词秒数 + 2秒缓冲
最终取整，夹在 20-30 秒之间（Seedance 2.5）
```

- 语速下限（通用默认）：7字/秒（约1.5秒10-11字）
- 好医保系列（中老年/门诊险/少儿，快节奏口播）：7字/秒（约1.5秒10-11字）
- 长钱保系列（慢节奏口播）：6字/秒
- 好医保·少儿长期医疗（53408，医疗/重病题材）：7字/秒（与好医保系列一致；重症/病房剧情仍以7字/秒为准，不再用更慢语速）
- **+2秒缓冲**：台词说完后留2秒收尾/衔接，避免"说完画面卡着不说话"或"台词没说完被截断"
- 示例（通用7字/秒）：180字 ÷ 7 = 25.7秒台词 → 27.7 → **28秒**；220字 ÷ 7 = 31.4秒 → 夹到上限30秒

### 分段（extend）规则

> **完整算法见 [`segmentation_packaging.md`](./segmentation_packaging.md)（唯一权威）**。要点：
- 拍平成句子流，按**句读边界（。！？）**切，长句说不完放下一段同角色承接，绝不切半句
- **句子流均匀打包**：目标190字/段、硬上限205字（7字/秒）；duration 按台词实际需要取 10/15/20/25/30（5s步进），短段给10s不硬撑20s
- 禁止给每镜头固定+2.5s动作预算（会堆空洞→拖音一顿）；场景切换必须落段边界+显式转场
- extend段必须写"接着上段继续说、不重新起头、不冷场"
- 质检加**ASR总字数对照**：ASR显著多于期望=模型自由发挥/重复，重做

- 长文案在**语义停顿处**（。！？）切两段，分别算时长
- P1 = text2video（前段），P2 = reference2video（后段，承接P1）
- 短文案（<约22秒）单段即可，不强制extend

### 多版本矩阵（一个脚本 × N 版本）

同一脚本可批量产出多版本（典型：3普通话 + 四川话 + 东北话 = 5条）：
- **台词完全相同**（同一份 atomic 文本），只改 `@VOX` 音色卡的口音维度，画面/prompt其余一致
- 方言卡写法：地道方言腔+用词口语化，但"吐字清楚、可被全国观众听懂"；脚本正文仍用规范普通话书写，口音只在VOX卡描述，不在正文写方言字
- 编号：一个脚本占连续N个水印号（如脚本1=001-005：普通话A/B/C、四川话、东北话）；命名 `产品名-日期脚本N-版本.mp4`
- 方言版 ASR 识别误差天然偏大，DIFF 以人工听感为准，不机械套普通话replace规则

### 版权随机失败处理

Seedance 报 `copyright restrictions` 多为**随机撞库误判**（非内容违规）：断点续跑 skip 已完成，失败段换 key/种子原样重试，通常即过；连续失败再微调人物外貌。不要误判为医疗/内容审核去改脚本。

### 模式判定

- **单段模式**：修正后总时长 ≤ 模型单段上限 → 一次 text2video 调用
- **extend模式**：修正后总时长 > 模型单段上限 → 前半段 text2video + 后半段 reference2video + ffmpeg拼接
- **时长计算公式**：`修正后总时长 = A念词(口播字数÷语速) + B停顿(逗号0.3s/句末0.7s/角色切换1.15s) + C纯动作镜头(1.5-3s/个) + D段末缓冲(1.5-2s)`。完整算法见 `segmentation_packaging.md` Step 6(唯一权威)。

### 不空窗要求（extend防"中间不说话"）

- P1 prompt 明确：**从第1秒就开口、全程连续口播、禁止不说话画面/停顿空镜/沉默过渡**
- P2 prompt 明确：**从第0秒立刻继续开口、与前段无缝衔接**，且 P2 prompt 里要**带上该段的台词文本**（否则模型不知道说什么）
- 产品名等长词必须完整念出，不许省略（见下方）

### 字幕SRT生成标准流程（ASR词锚定 + LLM语义断句）

**核心：时间戳永远用ASR词，LLM只给断点位置（不返回时间、不碰时间轴）。**
ASR词级数据的特点：词与词之间 gap 常为0（快口播无停顿），所以**不能靠停顿断句**，必须靠语义。

1. **ASR识别**：火山VC返回 utterance(句子级) + words(词级，每字精确start/end)；**words 先直出落盘为逐字稿**（`字幕/{名称}_逐字稿.srt` + `{名称}_words.json`，不经LLM，见 `asr_processing.md` 第10.5章）——下面 2-8 步产出的口播字幕SRT 是**逐字稿的派生产物**（复用同一份 words，不另跑一次 ASR）
2. **短句直接用**：utterance ≤13字 → 直接作为字幕行（火山语义分句，约80%）
3. **长句LLM断句**：utterance >13字 → 只把该句纯文本发LLM：
   - system：断句专家，按语义用`<br>`分段，每段≤12字，在"的/了/在/符合条件/可以投保"等边界后断，不切断词语，**不改字不增删**
   - LLM只返回`<br>`分隔的短句（无时间戳，prompt极短，8-12秒返回，低并发2-3不超时）
4. **顺序对齐（全局词序，关键）**：把每个utterance断成的段按顺序排成"目标字数序列"，用**一个全局词指针**顺序消费ASR全部词（累计词长==段字数时切）。**禁止按utterance时间窗口过滤词**（`w.end<=u.end+0.3`）——跨utterance边界的词会被漏掉丢字（实测"隐患"的"患"[8.56-8.84]落在边界外被丢）。末段吞掉所有剩余词，保证总字数严格守恒
5. **校验（LLM断点必须过）**：
   - 字数守恒：SRT总字数 == ASR词总字数（逐字对齐，零丢字零重复；这是硬指标，比逐段拼回校验更可靠——时间窗口漏字会被他处计数抵消掩盖）
   - 字数校验：每段≤13字
   - 拼回校验：LLM各段去标点拼接 == 原utterance去标点（防改字）
6. **残行合并**：切分后单字残行（非语气词 嗯/啊/哦 等）并入前一行（防"2026版"的"版"落单）；语气词单字行保留
7. **降级策略**：LLM失败/校验不过 → **换key重试**（3把key各试2轮）→ 全失败标记 **WAITING_USER**，不产出SRT（宁可不出不出废）。**禁止本地机械切字兜底**（凑N字一刀会切破产品名/数字，历史上"11字硬切"产出的字幕全是语义切断的废品——与 wf_verification.md Step 5"禁止本地机械切字"统一）
8. **绝不切词**：所有切分通过"顺序累计词"实现，切点在词与词之间，不会切断一个词

> 为什么不直接用LLM时间：LLM时间戳是猜的不可靠；ASR词时间是真的。LLM只回答"这句在哪断"，时间由词锚定。
>
> 工程要点：批量跑用**子进程隔离**（每个视频独立python进程，`subprocess.run`），单进程连续处理几十个视频后ffmpeg/requests会C层硬崩溃（exit 4无traceback）；子进程退出即释放资源，单崩不影响其他、天然断点续跑。并发3个子进程relay可扛。参考实现 `精华部分/大语言模型/scripts/_srt_one.py`（单视频）+ `_srt_run_par.py`（并发驱动）。
>
> **同音声调判定依赖 `pypinyin`**：wf_verification 的单字差异过滤（同音同调=ASR误差跳过、声调不同=错误、异音=错误）需要 `pip install pypinyin`；无该库时降级为"单字差异默认不跳过（宁多报不漏报）"。

### 断句与字幕字数规范（三个值分别用在不同阶段，勿混淆）

| 数值 | 阶段 | 用途 | 原因 |
|------|------|------|------|
| **5-8字** | SCRIPT_ATOMIZE（脚本原子化断句） | 给视频生成/TTS用的断句，控制每句长度 | 句子短一点TTS发音更清晰，视频生成时口型对齐更容易，避免一口气念太长导致吞字 |

### 时长预估公式

**预估时长（裸念词,仅供初步估算）**:
```
预估时长 = 口播字数(去括号后) ÷ 语速下限(字/秒)
```
- 语速下限 = 该项目的最慢语速（TTS prompt已约束，实际不会比这更慢）

> ⛔ **单段/extend 的正式判定不用预估时长,用「修正后总时长」** = 预估时长 + 停顿(逗号0.3s/句末0.7s/角色切换1.15s) + 纯动作镜头(1.5-3s/个) + 段末缓冲(1.5-2s)。完整算法见 `segmentation_packaging.md` Step 6。
> （预估时长会少算停顿/动作/缓冲,密集对话场景误差可达十几秒,直接用它判档位会漏判 extend。）
- 修正后总时长 ≤30s → 单段模式
- 修正后总时长 >30s → Extend模式(前30s+后段拼接,可超60s)

## 画面与技术约束 (All Projects)

### 视觉基调
- **风格**：高调通透为统一基底（高曝光、低对比、阴影提亮不压死、肤色保护不偏黄、整体低饱和）
- **场景化亚型**：不要全片一个调子，按场景从 [`style_palette.md`](./style_palette.md) 选通透亚型——诊室/产品口播=清透冷白，走廊/ICU=冷蓝底，居家客厅=日系空气感，餐桌/傍晚=暖通透，儿童/母子=柔粉，出院收尾=清晨通透
- **锁片规则**：同一亚型关键词每个镜头 STYLE 段重带（Seedance 无状态）；亚型切换只在 reference2video 段边界、写明新光源，单段内不换调；4 条基底关键词（low contrast / lifted shadows / natural skin tones / low saturation）必带
- **禁忌**：禁止空镜/风景开场；禁止字幕/文字/logo/换脸/畸变/横置/暗调；禁动态光影与 rack focus（见 prompt_craft_guide v3.7）

### 声音质量
- **连贯性**：句间不停顿，禁止句间沉默超过 0.3s
- **同步性**：生成时必须携带台词/旁白，确保口型对齐

## 流程与记录

### Extend 模式 (针对单次生成上限 > 30s 的处理)
1. **Step 1 (0-30s)**: 使用 `text2video` 模式，提交完整口播的前半段。
2. **Step 2 (30s+)**: 使用 `reference2video` 模式，传入前半段视频作为 `VideoList` + 续写 Prompt。
3. **Step 3**: 使用 `ffmpeg` 进行无损拼接。
