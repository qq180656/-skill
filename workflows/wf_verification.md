# 校验子流程

## 前置条件
- 视频文件已生成完成
- 原子脚本列表（`atomic_scripts.json`，其 **spoken** = 期望朗读文本 expected_readback_text）已就绪 —— **这是发音 DIFF 的唯一基准**
- 原始脚本和警示语列表已就绪 —— **仅用于 WARN_MATCH 提取警示语**，不用于发音 DIFF

## 依赖知识库
- `knowledge/templates/shot_logic_review.md` — 镜头逻辑自审（场景状态表+镜头间连续性自审+保险视频特化检查项，镜头重做后全量校验时复核镜头逻辑）
- `knowledge/tts_optimization/pronunciation_rules.md` — TTS规避词表（同音异形判定+数字读法规则）
- `knowledge/video_parameters/config_matrix.md` — 字幕断句与字数规范
- `knowledge/video_parameters/asr_processing.md` — ASR处理规范（词级时间戳导出/逐字稿生成）
- `knowledge/video_parameters/subtitle_burnin.md` — 硬字幕烧录规范（SRT转ASS+烧录参数+校验）

## 执行步骤

### Step 1: ASR识别 (ASR_TRANS)
- 工具: 调用ASR识别工具（输出词级时间戳）
- 输出: WordTime列表（text + start_sec + end_sec + 置信度）→ **直出落盘为逐字稿** `{名称}_逐字稿.srt` + `{名称}_words.json`（存 `{项目}/{日期}/字幕/`，见 Step 5a）
- 精度要求: 词准确率>99%, 时间戳误差<0.1秒
- **精度不达标处理**：整体置信度<0.95 → 标"低置信度"，DIFF该段用更宽松匹配（置信度<0.5跳过阈值降到<0.3）；时间戳误差>0.1s → 字幕对齐时人工标注提示、不阻断；整段ASR空结果 → 标ASR失败进 WAITING_USER，建议人工审核或重生

### Step 2: 文本清洗 (TEXT_CLEAN)
- ASR逐字稿（Step 5a 的 `{名称}_words.json`，ASR words 直出）输入LLM加标点/断句 → **派生**口播字幕SRT（Step 5b）；逐字稿本身保持 ASR 原样不被改写
- 标点规则:
  1. 每段不超过14个中文字（最终交付字幕标准，参见 config_matrix.md 断句与字幕字数规范）
  2. 语义完整处加逗号, 不拆产品名/数字/核心术语
  3. 同音纠错: 百分百→100%, 好质保→好医保, 个头条件→符合条件（纠错回**原子脚本对应词**=期望朗读文本，不替换为同义词）
- 对齐保护: 对齐前替换占位符, 对齐后还原
  - **占位符清单**（映射存 _session/alignment_map.json，DIFF后还原）：产品名特殊字符 好医保·中老年→[PROD_01]、好医保·少儿长期→[PROD_02]；小数 15.08元→[NUM_01]、400万→[NUM_02]；百分比 100%→[PCT_01]；版本号(2026版)原子化已省略、不进DIFF无需占位

### Step 3: 发音差异分析 (DIFF_ANALYSIS)
- ASR逐字稿（**取 Step1 纠错前的原始识别文本**，不用 Step2 同音纠错后的文本——否则念错会被纠错抹平漏检）vs **原子脚本列表（`atomic_scripts.json` 的期望朗读文本，非原始脚本）** 全文diff
  - 基准必须是原子化后文本：原子化已剥离括号警示语、删除删除级词（息肉/超声）、按 pronunciation_rules 省略"（2026版）"等不念内容。**用原始脚本做基准会把这些"本就不该念"的内容误判为漏念/多念，导致对含"(2026版)"等产品的无限重生（历史缺陷，此处已修）。**
- 三类差异及去向:
  - replace: 同位置文字不同 = 发音错误 → 进 `wf_correction.md`（TTS克隆+音频替换，AUDIO_REPAIR）
  - insert: 原子脚本有、ASR没有 = 真漏念；delete: ASR有、原子脚本没有 = 真多念
    - **粒度分级**：单/双字漏念（可能语速快吞音）→ 先 AUDIO_REPAIR 补、失败再 VIDEO_REDO；3-5字词组漏念/整句漏念(>5字) → VIDEO_REDO 重做该镜头；整句多念(delete>5字) → 必须 VIDEO_REDO（多余整句无法音频切割移除）
- 过滤规则: 置信度<0.5跳过/单字差异按同音规则判定/纯数字跳过/超10字replace跳过（注：数字读法错误另见 pronunciation_rules 数字读法规则，不受"纯数字跳过"豁免）
  - **同音异形判定**：单字差异+拼音相同+声调相同=ASR识别误差跳过；拼音相同+声调不同=声调错误进replace；拼音不同=发音错误进replace；无拼音库环境单字差异默认不跳过（宁多报不漏报）

### Step 4: 警示语匹配 (WARN_MATCH)
- **前贴跳过此步骤**（前贴无警示语，不生成警示语SRT，不触发E007）
- 成片执行以下操作：
  - 从原始脚本提取所有disclaimer警示语
  - 将每个警示语挂载到对应触发句的时间轴
  - **触发句匹配容错**：精确匹配直接挂；模糊匹配（编辑距离≤2且核心词一致）挂并标"模糊匹配建议人工确认"；无法匹配标E007进WAITING_USER；一个触发句匹配多候选取时间轴最近并标注
  - 输出警示语SRT: 时间轴与对应正文完全对齐
- **警示语泄漏检查（口播里是否念了只该做字幕的内容）——以该产品 atomic 正文为基准，禁止跨产品套词表**：
  - 判定一个短语是"口播卖点"还是"只做字幕的警示语"，唯一依据是**当前产品脚本的 atomic_scripts（口播正文）**：在正文里=本该念、ASR念出正确；只在括号 disclaimer 里=不该念、念出才算泄漏。
  - 同一句话在不同产品归属不同：如"赔付80%/住院个人承担一万以上按100%/126种大病/三甲特需部"，**少儿53408客户定稿写在角色台词里（该念）**，而中老年52973版本在括号警示语里（只做字幕）。
  - 因此不能用一张固定的"警示语关键词表"扫所有产品（会把口播卖点误报成泄漏，E2E实测踩坑）；正确做法：取该条 `atomic.spoken` 全集，ASR逐字稿里出现的、凡在 atomic 口播全集中的一律放行，只对"atomic 不含、但原始脚本括号 disclaimer 含"的短语报泄漏。
  - 剥离环节先保证混合括号（`(…）`开半闭全异体配对）已清干净（深度计数法，见 entry_direct Step1），再做此检查。

### Step 5: 字幕文件生成

**本步骤产出两种不同粒度的字幕文件，用途不同，都必须生成。二者是「源头 ↔ 派生」关系：`5a 逐字稿 → LLM语义断句 → 5b 口播字幕`，不是各自独立从 ASR 生成两份。**

两类文件**同放 `{项目}/{日期}/字幕/`**（与警示语SRT同目录，**不另建 `逐字稿/` 子目录**）。

#### 5a. 逐字稿（字级时间戳，审核/剪辑/对口型用）—— **字幕链路唯一源头**
- ASR 返回的 words **每个字单独一行**，带精确 start_sec/end_sec
- 格式：SRT，每条只有1个字（或ASR返回的最小单元），时间戳精确到毫秒；UTF-8 **without BOM**、换行LF、序号从1递增不跳号
- 命名：`{名称}_逐字稿.srt`（交付目录带序号前缀 = `{序号}_{名称}_逐字稿.srt`）
- 路径：`{项目}/{日期}/字幕/`
- 用途：精确对口型、剪辑定位、审核校对（"第3.16秒说了'还'字"）；同时是 5b 口播字幕与字幕烧录（`subtitle_burnin.md` Step 2）的**时间轴来源**
- **直接从 ASR words 导出，不经 LLM，不做任何断句/合并/纠错/加标点**（保持 ASR 原始粒度与原始识别文字，含错字；纠错只在下游 DIFF/字幕环节做，不回写逐字稿）
- 同时存一份 JSON 格式（`{名称}_words.json`，同目录），便于程序读取：
  `[{"text":"阿","start":0.32,"end":0.36}, {"text":"嚏","start":0.36,"end":0.56}, ...]`
- 参考实现：`scripts/skill_config.py` 的 `words_to_transcript_srt()` / `words_to_json()`；规范详见 `knowledge/video_parameters/asr_processing.md` 第10.5章

#### 5b. 口播字幕SRT（句级，观众看/烧入用）—— **由 5a 逐字稿派生**
- **派生关系**：LLM 只决定"在哪断句"，时间戳一律取 5a 逐字稿的词时间戳；**禁止为出口播字幕另跑一次 ASR**（会与逐字稿不一致且无法追溯）
- **ASR词时间戳 + LLM语义断句**（≤13字/行）。文本以 atomic 口播正文为准（不用有错字的ASR原文），LLM按语义断句，ASR词做时间锚点。**禁止本地机械切字**；LLM 429/超时→等待重试或换key，连续不可用进 WAITING_USER，不用本地切顶替。
- 命名：`{名称}_口播字幕.srt`（交付目录带序号前缀）；路径：`{项目}/{日期}/字幕/`
- **SRT格式规范**：序号从1递增不跳号；时间轴 `HH:MM:SS,mmm --> HH:MM:SS,mmm`（逗号分隔毫秒非句号）；每条≤2行、每行≤14中文字；换行符LF(\n)、块间空一行；编码UTF-8 **without BOM**（有BOM自动去除）
- 口播字幕SRT: 每行14字, 产品名独立段, 默认不烧入视频（软字幕）
- 警示语SRT: 字体更小, 位于口播字幕下方, 时间轴同步（成片才有，前贴跳过）
- **硬字幕（烧录）**：客户要"加好字幕的成片"时，按 [`../knowledge/video_parameters/subtitle_burnin.md`](../knowledge/video_parameters/subtitle_burnin.md) 执行——SRT 必须转 **ASS**（禁直接烧 SRT），口播42pt/警示语28pt、思源黑体(回退Noto Sans SC)、画面下1/6、产品名品牌色、双层合并为单ASS；CRF18、音频copy；命名`{名}_burned.mp4`，**同时保留无字幕原版+独立SRT**（双版本交付）；烧后5项自动+4项人工校验
- 发音错误标注SRT: 仅在检测到发音错误时生成
- 压底/末尾字幕SRT: 合规规则要求的必加提示，固定位于画面底部，时长覆盖全片或指定片段；仅在产品专属规则明确要求时生成
- **多SRT时间轴布局校验**：口播与警示语可重叠（警示语在下方小字）；发音错误标注SRT不得与口播时间轴重叠（不同视觉样式）；压底可与口播/警示语重叠（固定底部）；同屏最多3条字幕（口播+警示语+压底），超出调压底显示时段
- 审核文档: ASR逐字稿（**加标点的可读文本版**；逐字稿**文件** `_逐字稿.srt`/`_words.json` 存 `字幕/`） + 触发句警示语对应表 + 原始脚本

### Step 6: 检测报告 → 流转判定

- **零差异**（DIFF无问题 + 警示语全挂载）→ 标"自动通过"，**直通 DELIVERING**（跳过 CORRECTING）
- **有差异** → 生成检测报告（按严重度排序：insert/delete > replace > E007），**进入 CORRECTING**（`wf_correction.md`）自动纠正
- 检测报告包含：差异类型/位置/时间轴/原文vs ASR/严重度/建议纠正策略
- **VERIFYING 只检测、不修复**——所有纠正动作在 CORRECTING 阶段执行
