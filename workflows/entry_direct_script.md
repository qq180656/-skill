# 路径A：完整脚本直入流程

## 适用场景
用户直接粘贴或上传了完整口播脚本（可能含括号警示语，也可能不含）。

## 执行步骤

### Step 1: 脚本解析 (SCRIPT_PARSE)
- 输入: 用户原始脚本文本
- **脚本格式容错策略**（用户标记格式不一）：
  - 括号 `（）`/`()` 或方括号 `[]` 内内容 → 优先识别为警示语候选
  - **混合括号必须兼容**：客户原稿常出现开半角闭全角 `(符合条件可投保）`、开全角闭半角等异体配对。剥离时按"遇任意开括号 `(`/`（`/`[` 即深度+1、任意闭括号 `)`/`）`/`]` 即-1、深度内字符全删"处理，**不要求开闭同类型**；否则警示语会残留进口播被TTS念出（E2E实测缺陷）。多余未配对闭括号直接丢弃。
  - 无标记纯文本 → 全部识别为口播正文
  - 无法确定是否警示语 → 先提取，Step 3 与产品专属警示语库比对：匹配成功归类警示语；未匹配归口播正文并标记"待确认"
- 动作:
  1. 识别脚本结构：提取口播正文 vs 括号/方括号内警示语
  2. 识别场景类型：单人口播 / 多人对话
  3. 识别角色信息：角色数量、性别、方言等
  4. 确定项目类型：前贴 vs 成片（按 `router.md` §5 统一规则判定）
- 输出: 结构化脚本对象（口播文本 + 警示语列表 + 元信息）

### Step 2: 脚本原子化拆解 (SCRIPT_ATOMIZE)
- 输入: 结构化脚本对象
- 动作（按顺序执行）:
  1. **去括号**: 从口播正文剥离所有括号警示语，仅保留要朗读的文字
  2. **断句**: 每5-8个中文字加逗号断开，在语义完整边界断句（TTS原子化断句，与最终字幕≤14字不同，参见 config_matrix.md 断句与字幕字数规范；断句规则详见 knowledge/tts_optimization/script_writing_rules.md）
  3. **TTS空格注入**: 对所有空格级问题词前后各加一个空格，删除级问题词（息肉/超声）整词删除（参见 knowledge/tts_optimization/pronunciation_rules.md）
     - **TTS空格仅作用于口播朗读文本**（供语音合成），**最终字幕不显示这些空格**；分镜/字幕文本从原始口播正文提取，保留正常中文排版，不携带TTS空格
  4. **数字保护**: 15.08元/100%/400万等数字保持完整不拆（详见 script_writing_rules.md 数字保护规则）
  5. **语速校验**: 计算每段原子脚本的字数/预估时长，确保落在基准语速±0.5字/秒区间（好医保系列7±0.5，长钱保6±0.5）
     - 超标（单句太长）→ 二次断句或插入空格
     - 不足（单句太短）→ 检查是否过度断句，合并相邻短句
     - **二次断句回溯**：语速校验触发二次断句后，**必须重跑第4步数字保护校验**确认数字未被拆开；若二次断句会拆数字，则数字所在句保持不动，改为对其他句子更细断句/合并短句来调节总时长
  6. **时长预估**: 口播总字数 ÷ 基准语速 = 预估时长 → 决定单段/extend
     - 好医保系列（中老年/门诊险/少儿）：7字/秒
     - 长钱保：6字/秒
     - 通用默认：7字/秒
- 输出: 原子脚本列表，每个原子含 {atom_id, spoken(=期望朗读文本), est_duration, warning_ref}（注：字段名以 `atomize_script.py` 实际输出为准,文档中 `text`/`spoken` 均指同一字段——原子化后的期望朗读文本;`fidelity_diff.py` 读的是 `spoken` 字段）

### Step 3: 合规校验 (COMPLIANCE_CHECK)
- **依据文件（调度权威，必读）**: `knowledge/compliance/trigger_conditions.md`（触发时机与阻断行为）+ `knowledge/compliance/rules.md`（三层叠加体系+警示语映射+前贴豁免），再按下述三层逐层读取 通用/险种/产品 文件。三者共同构成 COMPLIANCE_CHECK 的规则来源，**不得只凭本文件内联描述执行**。
- 输入: 原子脚本列表 + 警示语列表 + 项目标识（产品名+渠道+险种）+ 类型（前贴/成片）
- 动作: **根据类型决定校验深度，逐层读取规则文件**

> ⛔ **三层合规必须逐层 Read 文件,并在合规报告中列出证据**:
> 
> | 层 | 必须 Read 的文件 | 合规报告必须包含 |
> |---|---|---|
> | 第一层·通用 | `通用合规/保险投放素材通用规则（全险种适用）.md` | "✅ 通用合规已读,检查项:禁用词/主体/形象/绝对化" |
> | 第二层·险种 | `险种专项/{对应险种}-合规要求.md` | "✅ 险种专项已读:{险种名},检查项:..." |
> | 第三层·产品 | `产品专属/{产品名}-投放注意事项.md` | "✅ 产品专属已读:{产品ID},检查项:..." |
> 
> **合规报告如果缺任何一层的"已读"证据 = Pre-flight 第 1 项 FAIL,不允许生成。**
> "凭记忆执行"/"只读了一层就出报告"/"没列出读了哪三个文件" = 不合格。

**多层命中优先级**：同一表述被多层命中时（如"都能赔"同时触发层1禁用词"都"和层2禁止承诺），**合并展示、按严重度排序：层1硬红线 > 层2险种禁令 > 层3产品专属**，替换建议取最严格的一条，避免对同一句话给多条冲突替换。

#### 前贴 vs 成片的合规差异

| 维度 | 前贴 | 成片 |
|------|------|------|
| 利益点 | 无（只引产品名） | 有（讲保障/保费/比例） |
| 警示语 | 无需挂载 | 必须逐句挂载 |
| 合规层级 | 三层全部读取（禁用表述校验） | 三层全部读取（禁用表述+警示语挂载） |
| 产品专属缺失时 | 警告+记录，不阻断（前贴不涉及利益点，禁用表述风险较低；需告知用户产品专属规则缺失） | 阻断，WAITING_USER |
| 脚本标注文档 | 不生成（无警示语） | 必须生成 |

#### 判定当前脚本是前贴还是成片：
- 按 `router.md` §5「前贴/成片类型统一判定规则」执行，不在本文件内重复判定逻辑。
- 判定结果决定本步骤校验深度（见上方差异表）和是否生成脚本标注文档。

#### 第一层：通用合规（knowledge/compliance/通用合规/）
扫描全险种适用的硬性红线：
1. **禁用词扫描**: 绝对词(都/全/均/统统/百分百)、承诺词(一定/保证赔/秒赔)、误导词(唯一/首选/独家)、极限词(最好/最便宜)
2. **焦虑营销检测**: 是否含恐吓/卖惨话术（"家破人亡/倾家荡产/不买就完了"）
3. **形象合规**: 是否使用医生/护士/新闻主持人形象推荐
4. **主体合规**: 是否错误归属承保主体（"支付宝的保险"→应为"XX保险公司承保"）
- 命中任一 → 标记问题项 + 给出替换建议（**不自动改写**）
- ⚠️ 白名单：层2/层3官方推荐合规话术中**合法出现**的"都/均/全"等（如门诊险"无论大病小病，只要属于责任范围内，都可以按条款约定申请理赔"、意外险"…均可按约定申请理赔"）**不告警、不替换**，避免把已审定的合规句改坏

#### 第二层：险种专项（knowledge/compliance/险种专项/）
根据险种类别（医疗险/重疾险/意外险/寿险年金/宠物险/车险等）读取对应文件：
1. **表述规范**: "0免赔"→必须写"0免赔额"、"100%报销"→必须写"100%比例报销"
2. **禁止承诺**: "都能赔/看病不花钱/确诊就赔"
3. **医保关系**: 不能贬低医保，只能说"医保的补充"
4. **续保表述**: 必须区分一般医疗与特定疾病责任，不能笼统说"终身续保"
5. **带病投保**: 不得宣传"带病可投"，须写"符合条件可投保"
6. **渠道引导词**: 结尾引导必须是"点击视频下方链接"（抖音等信息流渠道通用要求，不能说"搜支付宝/去应用商店"；其他渠道以产品专属规则为准）
7. **代词校验**: 指代产品用"它"不用"他/她"
- 命中 → 标记 + 给出险种合规替换

#### 第三层：产品专属（knowledge/compliance/产品专属/）
根据具体产品读取对应文件（如"好医保·中老年长期医疗(2026版)-52973投放注意事项.md"）：
1. **触发句↔警示语完整性**: 逐条核对每个触发句后是否紧跟正确的警示语
2. **"责任内"前缀规则**: 口播已说"责任内"→警示语不重复加；口播没说→警示语须加（责任内）前缀
3. **0免赔额/1元/100%强制警示语**: 凡涉及必须加完整免赔额警示语
4. **保费表述**: 说了具体数字→加（有医保）（保费随不同年龄...）；没说数字只说"不贵"→加完整保费参考
5. **产品特有约束**: 该产品额外的禁止/必加项
- 缺失警示语 → 自动补挂
- 警示语不完整 → 补全
- 触发句无对应警示语 → 标记E007，暂停询问用户

#### 校验结果汇总
- 三层全部通过 → 输出合规报告(Pass) + **脚本警示语标注文档**
- 有问题项 → 输出合规报告(Fail) + 逐项修正建议
  - 可自动修正的（禁用词替换/警示语补挂）→ 自动修正后标记
  - 需用户决策的（边界模糊/多种替换方案）→ 暂停，展示选项给用户

#### 脚本警示语标注文档（COMPLIANCE_CHECK核心输出）
生成前的确认文档，用户看完确认"对"才开始跑视频。

**脚本序号规则**：从01开始，格式 `脚本01_场景描述`；标注文档内触发句序号与 Step 2 输出的 warning_ref / atom_id 对应，确保可追溯；多条脚本各自从01独立编号，不跨脚本续编。

格式：

```markdown
# {产品名} - 脚本警示语标注
## 脚本{序号}: {描述}

### 标注正文

{逐句列出口播正文，每个触发句下方紧跟↓+完整警示语}

例:
符合条件可以投保，最高70岁也能买
↓（符合条件可投保）（由高血压或糖尿病引发的并发症需关注健康告知要求，乳腺结节≥4级、肺结节＞3mm有除外承保，具体以健康告知、核保结论为准）

责任内是可以申请理赔的
↓（责任内）（符合条款约定可赔付）（住院费、手术费和医疗费申请理赔需要满足对应的就诊场景和条件）

### 警示语汇总表

| # | 触发句 | 警示语（完整，不可省略） | 合规依据 |
|---|--------|--------------------------|----------|
| 1 | 符合条件可以投保 | （符合条件可投保）（由高血压或糖尿病引发的并发症需关注健康告知要求，乳腺结节≥4级、肺结节＞3mm有除外承保，具体以健康告知、核保结论为准） | 产品专属-慢性病可投保 |
| 2 | 最高70岁也能买 | （符合条件可投保） | 产品专属-基础信息 |
| ... | ... | ... | ... |

### 合规校验结果
- 第一层通用: ✅/❌ + 具体问题
- 第二层险种: ✅/❌ + 具体问题
- 第三层产品: ✅/❌ + 警示语匹配数/总触发句数
```

**硬约束**：
- 警示语必须显示完整内容，禁止用省略号(...)截断
- 每个触发句必须逐条列出，不可合并
- 合规依据必须标注来源层级和具体规则项

- 输出: 合规报告(Pass/Fail + 修正建议) + 脚本警示语标注文档
- 存储: `{项目名}/{YYYY-MM-DD}/脚本标注/{序号}_{名称}.md`

### Step 4: 分镜规划 (STORYBOARD)
- **⛔ 必经状态，禁止跳过直接进入 GENERATING。** 未经分镜设计的脚本数据文件不得用于视频生成——直接从口播文本套模板会导致场景单一、景别重复、运镜缺失、动作雷同（已复现：260915首批50条全是"候诊区近景+手机假UI"）。
- 基于原子脚本列表，进入 `wf_storyboard.md` 的**路径A模式**
- 路径A模式：直接基于口播文本语义和场景标注拆解镜头、构造画面 Prompt，不依赖 creative_design.md
- **场景推断确认**：若场景为推断（脚本无明确场景线索、走了决策树第4层中性室内），需在分镜总览标注"场景为推断"，并在 Step 5 READY 确认时单独提示用户确认场景选择
- 分镜产出（storyboard.md）需用户确认后进入 READY 状态

### Step 5: 生成前最终确认 (READY)
- 固定的生成前确认门，非临时暂停
- 展示最终确认清单：
  - 分镜方案（storyboard.md）
  - 脚本标注文档（成片）/ 口播文本（前贴）
  - 合规报告
  - 预估时长和模型参数
- 用户确认后进入 `wf_generation.md` 开始视频生成
- **修改回退分级**（不一律重跑整个阶段）：
  - 改单个警示语位置/措辞 → 直接改标注文档，不重跑 Step 3
  - 改口播正文内容 → 回 Step 2 重新原子化 + Step 3 重新校验
  - 改分镜运镜/景别 → 直接改 storyboard.md 对应镜头
  - 改分镜结构（增删镜头/改场景）→ 回 Step 4 重新分镜
