# 复盘子流程 (Retrospective Workflow)

## 定位
交付完成后、DONE 之前的**自我复盘**环节。回顾本次会话全流程,检出问题、总结经验、输出 skill 优化建议。目标:每次出片的踩坑经验闭环回规范,不让同样的坑下次还踩。

## 前置条件
- DELIVERING 完成,用户已确认收到产物
- 本次会话的所有中间产物/日志/检测报告可访问

## 执行步骤

### Step 1: 问题收集(逐维度自查)

按以下 6 个维度回顾本次会话,**每个维度列出:正常项 / 异常项 / 踩坑项**:

| 维度 | 自查内容 |
|------|---------|
| **发音** | ASR diff 发现了哪些 replace/insert/delete?哪些词反复念错?TTS 空格注入/删除级有没有漏?产品名念对了吗? |
| **画面** | 角色外貌跨镜一致吗?有没有变脸/融合/畸变?场景跳变?正反打轴线越轴?空间关系三要素齐全? |
| **合规** | 三层合规有没有漏检?警示语挂载齐全吗?有没有触发了但没挂的?产品专属红线(如门诊险"线上问诊")有没有踩? |
| **流程** | 有没有跳步(如跳过 STORYBOARD/READY)?路由判定对了吗?用户确认门有没有走到?CORRECTING 循环了几次? |
| **时长/分段** | ≤30s 合并了吗(没有过度拆镜)?>30s 拆段正确吗?段内有没有空洞/拖音?extend 承接自然吗? |
| **交付** | 产物齐全吗(裸视频/字幕/审核文档/日志)?目录结构对吗(素材/成片/成片_带字幕各归各)?命名规范? |

### Step 2: 根因分析

对 Step 1 发现的**异常/踩坑项**,逐条分析根因:

- 是**规范缺口**(规范没写、执行时没指导)→ 该补规范
- 是**规范矛盾**(两处规范冲突、执行时随机)→ 该收敛
- 是**执行偏差**(规范写了但没按规范走)→ 该加门拦/校验
- 是**模型能力边界**(Seedance 做不到,如真正的一镜到底)→ 该记录已知限制
- 是**参数问题**(语速/时长/Key 配错)→ 该改 skill_config 或 config_matrix

### Step 3: 复盘报告

产出 `{项目}/{YYYY-MM-DD}/_session/retrospective.md`,包含:

```markdown
# 复盘报告 — {项目名} {日期}

## 本次产出概况
- 脚本数/视频数/总时长/总费用
- 路径(A/B/C) + 生成路径(一/二)
- CORRECTING 循环次数

## 正常项(做对了的)
- ...

## 异常项(做错了、纠正后修好了的)
- 问题 → 根因 → 纠正方式

## 踩坑项(耗时长/反复修/差点没发现的)
- 坑 → 根因 → 建议优化

## Skill 优化建议
- [ ] 建议1: 补规范/改规范/加门拦(对应哪个文件)
- [ ] 建议2: ...
```

### Step 4: Skill 优化(按建议落实)

对 Step 3 的优化建议,判定:
- **可立即改**(文档 typo / 参数更新 / 门拦补充)→ 当场改、commit
- **需验证**(新规则需要下次出片验证)→ 记入 `meta/_skill_revision_context.md` 待验证队列
- **需用户拍板**(涉及流程变更/产品红线调整)→ 列出、等用户确认

### Step 5: 经验沉淀

将本次**真正有价值的新发现**沉淀到对应规范文件(不是所有踩坑都值得写进规范——只沉淀**会反复出现的、下次还会踩的**):

| 沉淀去向 | 什么该沉淀 |
|----------|-----------|
| `pronunciation_rules.md` | 新发现的 TTS 念错词(空格级/删除级) |
| `prompt_craft_guide.md` | 新发现的 Prompt 写法坑(某种描述导致画面畸变等) |
| `产品专属/*.md` | 新发现的产品拒审点 |
| `config_matrix.md` | 参数调优(语速/时长/并发等经验值) |
| `知识库其他文件` | 其他维度的经验 |

> ⚠️ **不沉淀的**:本次特有的一次性问题(如"某次网络超时")、已在规范中有但执行时漏了(这是执行偏差不是规范缺口)、用户个人偏好(存记忆,不存规范)。

## 约束
- 复盘**必做**,不可跳过(哪怕本次零差异全自动通过,也要走 Step 1 自查确认"确实没问题")
- 复盘不阻塞交付——产物在 DELIVERING 已交付给用户,RETROSPECTIVE 是交付后的内部改进
- 复盘报告存 `_session/`,不进交付目录(内部文档,不给客户看)
- Skill 优化改动必须 commit + push(不能只改本地,下次会话读不到)
