# 异步任务交付(所有生成/处理命令统一走此流程)

> **生图、生视频、超分、擦字幕**全部是异步任务,统一走"提交 → 轮询 → 下载 → 交付",不在各命令里各写一套。
> 对应实现:`scripts/image_to_video.py` 的 `_submit()` / `_poll()`,`scripts/batch_generate.py` 的 BatchRunner。

## 统一四步

```
① submit  ──POST 提交──► 拿 task_id(提交失败按错误类型处理,见下)
② poll    ──task_status 轮询──► status: queued/processing → succeeded/failed
③ download ──succeeded 后取 URL──► 下载二进制,校验大小>0、可解码
④ deliver ──► 写入对应目录 + 展示真实附件 + 登记台账
```

**铁律**:
- **提交成功不等于生成成功**——必须 poll 到终态。禁止 `submit` 后就向用户报告完成。
- **轮询间隔**:生图 6-10s、生视频 10s;最长等待 生图270s、单段视频 600s。
- **单次轮询失败不致命**:网络抖动只记日志继续下一轮,不立即判任务失败。
- **终态只有两个**:`succeeded`(进 download) / `failed`(按错误类型,见 wf_generation §4.5)。
- 下载/查询失败**绝不触发重复生成**——只重试取件,不重新提交(防重复扣费)。

## 批量异步(多任务并行)

- 多个任务**先全部 submit 拿一组 task_id,再统一 poll**——谁先 succeeded 谁先 download,不串行等。
- 并发上限:生图/生视频跨任务并发 ≤4;Key 按 `index % len(KEYS)` 轮转。
- 某任务失败只标记该任务,不阻塞其他任务;全部终态后统一汇总成功/失败清单。

## 错误分类(决定是自动重试还是上报用户)

| 类型 | 自动处理 | 上报 |
|---|---|---|
| 网络超时/500/单次 poll 失败 | 原样重试(取件重试,不重新生成) | 连续失败→暂停,告知用户 |
| 429/额度 | 换 Key;全超限→E014 | 用户充值/等次日 |
| copyright 撞库 | 换 Key+种子原样重试2次 | 3次仍拦→微调外貌(不改台词) |
| 内容审核 security_filter | 不重试 | 用户改画面描述 |
| 模型不可用 | 等30s重试1次 | 用户决定换模型(需确认) |

> 完整失败处理表见 `wf_generation.md` Step 4.5。本文件只管"异步交付时序",不重复错误细节。
