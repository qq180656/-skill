# 路径C：混合输入 (Entry Mixed)

## 适用场景
用户同时提供了**部分**脚本片段（>20字，仅覆盖某一段/某一句，非完整结构）和部分需求说明（如："做好XX项目的前贴，开头要讲...，脚本参考如下..."）。

**不属此路径**：完整脚本（有开头有结尾、>50字）+ 简单需求说明（产品名/类型/数量）→ 按路径A处理（见 router.md STEP 0 的完整性判定）。

**20字阈值来源**：<20字通常是需求描述片段（如"开头讲意外保障"），不足以构成可朗读的脚本句；>20字且有口语朗读特征（口语语气、完整主谓宾、可直接进TTS）才算脚本片段；15-25字边界难判时→优先走路径C（保留用户原文+补齐），避免误判为路径A/B丢失用户原文。

## 执行步骤

### Step 1: 分离解析 (Separation)
- 从输入中提取已确定的脚本片段（Text Content），标注其覆盖范围（开头/中间/结尾）
- 从输入中提取未确定的需求说明（Requirement/Brief），包括产品名/类型/数量/风格要求
- 确定项目类型：前贴(15-20s) vs 成片(弹性时长)
- **脚本片段覆盖范围判定规则**：
  - 含场景引入/人物出场 → 判为"开头"
  - 含产品名/CTA（如"点击了解""赶紧投保"）→ 判为"结尾"
  - 含利益点/对话互动 → 判为"中间"
  - 无法判定 → 标"未知"，Step 2 补全时按需求说明推断其位置

### Step 2: 缺口补全 (Gap Filling)
- 基于需求说明，结合 `knowledge/compliance/` 中的三层合规规则，补齐缺失的场景、台词或警示语
- 补齐约束：
  - 用户已提供的脚本片段**不修改**，仅补齐缺失部分
  - 补齐内容需过三层合规规则叠加（禁用词扫描 + 警示语挂载）
  - 前贴补齐内容不带利益点、不挂警示语
- 若缺失关键信息（产品名/类型无法确定）→ 跳转 WAITING_USER 询问用户
- **用户片段内含违规表述的处理**：
  - 用户原片段**不自动改写**；禁用词命中 → 在 Step 3 合并确认时高亮命中处 + 给替换建议，由用户决定是否采纳
  - 警示语缺失 → 成片时自动补挂（警示语非用户原文，补挂不违反"不修改用户片段"约束）
  - 用户拒绝修改禁用词 → 在脚本标注文档记风险项，仍进 READY，但 READY 确认时再次提示风险
- **补齐内容风格对齐**：
  - 用户片段为对话体 → 延续已有对话角色的语气补写
  - 单人口播 → 保持同一人称（我/你/咱们 前后一致）
  - 旁白体 → 保持旁白视角（第三人称叙述）
  - 无法判断风格 → 补齐内容标注"补齐风格为推断，建议确认"
- **补齐内容来源追溯标记**（每段补齐内容必须打标，Step 3 展示时呈现）：
  - 【Brief补齐】— 来自用户需求说明
  - 【险种模板补齐】— 来自 `knowledge/` 险种模板
  - 【合规补挂-层级N】— 警示语/免责补挂（N=命中的规则层级）
  - 【语义推断补齐】— 上下文语义推断所得
- **多条脚本片段处理**：
  - 用户片段数 < 需求脚本数 → 缺的脚本从零撰写（走路径B `entry_brief_only.md` Step 3 规则），并与用户片段风格对齐
  - 用户片段数 ≥ 需求数 → 截取前 N 条为成品，多余条目列为备选供用户挑选
  - 每条脚本独立过合规校验，但合规报告合并为一份输出

### Step 3: 合并与确认 (Merge & Confirm)
- 将补全内容与原始片段无缝合并，生成完整脚本
- **合并接缝展示规则**（提交确认时呈现）：
  - 用户原文 → 正常显示（不加标记）
  - 补齐内容 → 用【补齐】包裹（保留 Step 2 的来源追溯标记，如【Brief补齐】）
  - 合规补挂警示语 → 用 ↓ 标注
  - 禁用词命中处 → 高亮 + 附替换建议
  - 用户可选择：接受全部 / 只接受部分（未接受的补齐回到 Step 2 重新补全）
- 合并后的完整脚本提交给用户确认
- 用户要求修改 → 回到 Step 2 重新补全
- 用户确认后进入 Step 4

### Step 4: 原子化拆解 + 合规校验 + 分镜
- 同 `entry_direct_script.md` 的 Step 2（SCRIPT_ATOMIZE）、Step 3（COMPLIANCE_CHECK）、**Step 3.5（PRE_COMPLIANCE_GATE）**、Step 4（STORYBOARD）
- ⚠️ **路径C 也必须跑 Step 3.5 确定性合规前置门**：合并后的脚本（含用户原始片段+补齐内容）同样需跑 `python scripts/pre_compliance_check.py --product {产品} --type {前贴/成片} --file {脚本文件} --json --strict` 做硬兜底，处理逻辑同 `entry_direct_script.md` Step 3.5
- **前贴**: 三层全部读取（禁用表述校验），不挂警示语，不生成脚本标注文档
- **成片**: 三层全部读取 + 警示语挂载 + 生成脚本标注文档
- **用户片段已有断句的预处理**（SCRIPT_ATOMIZE 前）：
  - 已有合理的 5-8 字逗号断句 → 保留原断句，不做二次切分
  - 整段无逗号 / 断句间隔过长（单句无停顿 >12 字）→ 按 5-8 字标准重断
  - TTS 空格统一按 `pronunciation_rules` 注入（无论原片段有无空格，以统一标准为准）
- 分镜产出（storyboard.md）需用户确认后进入 **READY 生成前最终确认门**，再进入 GENERATING（与路径A/B 一致，不跳过 READY 门）
