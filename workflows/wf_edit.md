# 修改工作流 (Edit Workflow)

## 适用场景
用户对已有产物（脚本/分镜/视频/字幕）提出修改指令，包括换镜头、改台词、调风格、加字幕、删段、换 BGM 等。

## 依赖知识库
- `knowledge/templates/quality_control.md` — KEEP/CHANGE 修改协议
- `outputs/intermediate_artifacts.md` — 中间产物路径（用于定位待修改文件）

## 修改类型判定

收到修改指令后，先判定修改类型，决定回退到哪个阶段：

| 修改类型 | 典型指令 | 回退阶段 | 是否需重新生成视频 |
|----------|----------|----------|-------------------|
| **保留式** | 换BGM、加/删字幕、回退片段、换序、整片换色调、删段、加/换/删画面元素 | 直接后处理（不重生视频） | 否 |
| **音频级** | 替换某句配音、调音量 | 直接修改音轨 | 否（替换后重跑 ASR 校验） |
| **字幕级** | 改字幕文字、调字幕时间轴、加/删字幕 | 直接修改 SRT | 否（重新校验对齐） |
| **镜头级** | 换某个镜头画面、调某段运镜、改某镜头风格 | 回到 GENERATING（仅重做该镜头） | 是（仅该镜头） |
| **台词级** | 改某句口播文本、换措辞、加/删一句话 | 回到 STORYBOARD（修改对应分镜）→ GENERATING | 是（受影响的镜头） |
| **脚本级** | 重写脚本、换题材、改核心利益点、换产品 | 回到路径 A（脚本解析）或路径 B（创意设计） | 是（全片或大部分） |

### 保留式修改快速通道 — 平台适配

> 用户对现有画面满意，只做有界调整，不重新生成视频。平台提供以下后处理能力支持保留式修改。

| 修改需求 | 平台工具 | 说明 |
|---------|---------|------|
| 换BGM / 加BGM / 移除BGM | `render_video` bgm_audio_path | 传入新BGM路径重新合成；移除则不传bgm参数 |
| 加/删字幕 | `render_video` show_subtitle | true开启自动字幕，不传则无字幕 |
| 换字幕样式 | `render_video` subtitle_scene | 选择不同字幕模板 |
| 段级重排/删段 | `render_video` video_paths | 调整视频片段顺序或删除某段后重新拼接 |
| 整片换色调/风格 | `sandbox_process_video` | 视频后处理工具（按需） |
| 视频超分（画质增强） | `sandbox_process_video` ToolName=video_super_resolution | 支持720p→1080p→2k→4k→8k逐级超分 |
| 擦除画面内字幕 | `sandbox_process_video` ToolName=erase_video_subtitle | 擦除视频画面中已烧录的字幕 |

**保留式修改判定原则**：
- 用户明确说"画面不动/视频不变，只改X" → 保留式
- 用户说"换BGM/加字幕/删某段" → 保留式
- 用户说"画面质量不行/太模糊" → 保留式（超分）
- 用户说"画面有字幕要去掉" → 保留式（擦字幕）
- 判不清时先按保留式尝试，用户不满意再升级到更深层

### 视频超分与擦字幕 — 平台原生能力

#### 视频超分 (Video Super Resolution)
- 工具：`sandbox_process_video`，ToolName=`video_super_resolution`
- 参数：`OutputResolution` 支持 720p/1080p/2k/4k/8k，只能向上超分
- 适用场景：成片画质不够清晰、分辨率低于投放平台要求
- 保险项目典型用法：720p成片超分到1080p满足抖音投放要求

#### 擦除画面内字幕 (Erase Video Subtitle)
- 工具：`sandbox_process_video`，ToolName=`erase_video_subtitle`
- 适用场景：视频画面中已烧录字幕需要去除（如换用新字幕版本）
- 保险项目典型用法：旧版成片烧录了口播字幕，需要更换为警示语版字幕时先擦除旧字幕

### 混合修改规则
- 一次指令包含多个修改时，按**回退最深类型统一执行**（深度序：保留式 < 音频 < 字幕 < 镜头 < 台词 < 脚本，取 max）
  - 例："换 BGM + 改第 3 镜画面" → 按**镜头级**统一走（GENERATING 重做第 3 镜 + 音轨替换一并完成）
- 互不影响的修改**可并行**（如：视频 A 的字幕级修改 + 视频 B 的音频级修改，两者独立执行互不阻塞）

### 边界模糊判定
指令语义不明确落在哪一级时，按下表归位：

| 指令语义 | 归类 | 实际动作 |
|----------|------|----------|
| 改语气 / 改语速 | **台词级** | 只改 @VOX 音色卡参数（六维），重生受影响镜头的音画 |
| 改表情 / 改动作 | **镜头级** | 改该镜头 Prompt，重做该镜头 |
| 改场景背景 | **镜头级** | 变更场景参考图（ImageList 每镜重传），重做受影响镜头 |

- 不确定时**先按较浅层尝试**（如先当字幕级处理），用户不满意再升级到更深层，避免过度重生浪费额度

### 段内区间局部编辑

> 用户要求"把第X到Y秒重做/换掉"，区间小于一个完整段。

**前置判定（先判再执行）**：
- 多段项目成片（各 `shot_NN.mp4` 在 sandbox 中）→ **不走本条**：定位区间所在段，按保留意愿走保留式修改（原段入 VideoList 做编辑）或镜头级修改（重做该段）后重新合成。有原始参数与参考图，保真度更高
- 单段直出视频 / 用户上传的现有视频 → 按以下流程执行

**执行流程**（以源视频 15s、编辑 4-8s 区间为例）：

1. **切分**：用 ffmpeg 把源视频切成头段 / 待编辑段 / 尾段
```bash
ffmpeg -hide_banner -loglevel error -y -ss 0 -to 4 -i input.mp4 -c copy assets/pre.mp4
ffmpeg -hide_banner -loglevel error -y -ss 4 -to 8 -i input.mp4 -c copy assets/mid.mp4
ffmpeg -hide_banner -loglevel error -y -ss 8 -i input.mp4 -c copy assets/post.mp4
```
切分后用 ffprobe 确认各段实际时长（`-c copy` 切点吸附到最近关键帧，可能有零点几秒偏差）

2. **编辑中间段**：调用视频生成工具
   - VideoList 填待编辑片段路径
   - Prompt 格式：`对@视频1进行编辑：{用户要求的编辑描述}`
   - TaskType=edit，Duration 取待编辑段实际时长（取整）
   - 输出 `assets/mid_edited.mp4`
   - 调用未报错即视为成功，不重复生成多版

3. **拼接**：用 `render_video` 收口（禁止用 ffmpeg concat）
   - video_paths: [pre, mid_edited, post]
   - 继承原有 show_subtitle / bgm_audio_path 状态

4. **校验**：ffprobe 确认输出总时长符合预期

**规则**：
- 编辑区间在片头（从0s起）或片尾（到末尾）时，退化为两段拼接，省略对应的 pre/post 切分
- ffmpeg 只用于切分与探参，拼接一律走 render_video

## 执行步骤

### Step 1: 定位修改对象
- 从 `_task_ids.jsonl` 和交付目录中定位待修改的产物（视频/脚本/分镜/字幕）
- 确认修改范围：单条视频 / 多条批量 / 整个项目
- 读取 `intermediate_artifacts.md` 中对应阶段的中间产物路径
- **产物版本识别**（多版本共存时）：
  - 目录定位取**最高版本号**：`_v2` > `_v1` > 无后缀
  - `_task_ids.jsonl` 中同一产物按 `version` 字段**降序取首条**
  - 只有用户明说"改回第一版/改回 v1"才定位旧版本；**默认始终基于最新版修改**

### Step 2: 判定修改类型并执行

#### 音频级修改
- 直接用 ffmpeg 替换/调整音轨
- 修改后重新跑 `wf_verification.md` 的 ASR 识别（Step 1），确认音画同步
- 不需要重新生成视频
- **音量归一化**（必做）：
  - BGM 替换后：人声轨 **-16 LUFS**，BGM 轨 **-24 LUFS**；有人声时 BGM 侧链（sidechain）压低 **3–6 dB**
  - 单纯调音量（非替换）：以**原响度为基准**，调整后偏差 **≤ ±1 LUFS**
  - 用 `ffprobe`/`ffmpeg -af loudnorm=print_format=json` 复测，超标则重调直至达标

#### 字幕级修改
- 直接编辑对应 SRT 文件
- 修改后校验时间轴与音轨对齐
- 不需要重新生成视频

#### 镜头级修改
- 遵循 KEEP/CHANGE 协议：明确哪些镜头保留（KEEP），哪些重做（CHANGE）
- 仅对 CHANGE 标记的镜头重新调用视频生成
- KEEP 的镜头直接复用原视频文件
- **KEEP/CHANGE 接缝校验**（镜头级修改后必做）：在相邻 KEEP/CHANGE 镜头转场处，按 `knowledge/templates/visual_anchor_spec.md` 的 **7 维度比对清单 + GREEN/YELLOW/RED 分级**逐项校验并出 `seam_check` JSON 报告；不达标按该文件的**补偿策略矩阵**处理（CHANGE 镜头加 KEEP 末帧参考约束 / ffmpeg 色彩校准脚本 / KEEP 轻微调色统一影调）
- 重新做 SHOT_MERGE 拼接
- 重新跑 VERIFYING 全流程

#### 台词级修改
- 修改原子脚本列表中对应句子
- 重新过 TTS 优化（空格注入/发音规避）和合规校验（COMPLIANCE_CHECK）
- 若修改涉及警示语触发句，重新生成脚本标注文档并请用户确认
- 更新 storyboard.md 中对应镜头的 Prompt
- **时长重算**（改句后必做）：
  - 按语速标准（好医保系列 7 字/秒、长钱保 6 字/秒）重算受影响镜头时长
  - 新时长与原时长差 **≤ 1s** → 保持原生成参数（duration 不变），不分段
  - 新时长**超出原时长 ≥ 2s** → 重新判定单段 / extend，必要时**重分镜**（按 190 字/段、硬上限 205 字在句读边界切）
  - 同步更新 `storyboard.md` 中对应镜头的 `duration` 字段
- 重新生成受影响的镜头 → SHOT_MERGE → VERIFYING

#### 脚本级修改
- 回到对应入口路径：
  - 用户提供了新脚本 → 路径 A（entry_direct_script.md）
  - 用户只给了新需求 → 路径 B（entry_brief_only.md）
- 重新走全链路：脚本解析 → 原子化 → 合规校验 → 分镜 → 生成 → 校验 → 交付
- 原产物保留在原日期目录，不覆盖；新产物存入新日期目录

### Step 3: 修改后校验
- 无论哪种修改类型，修改完成后必须重新跑 `wf_verification.md` 中受影响的校验项：
  - 音频/台词修改 → 重跑 ASR + DIFF_ANALYSIS
  - 成片且修改了触发句 → 重跑 WARN_MATCH
  - 镜头重做 → 全量校验
- **未修改部分回归校验**（防止改动波及无关区域）：
  | 修改类型 | 回归校验范围 |
  |----------|-------------|
  | 台词级 | 除本句外，校验**前后各一句**的警示语挂载是否仍正确 |
  | 镜头级 | 校验**相邻 KEEP 镜头的转场接缝**（外貌/光影/空间三项） |
  | 音频级 | 校验**全片音画同步**（不限改动段） |
  | 字幕级 | **仅校验修改段**，不扩大范围 |
- 校验通过后进入 `wf_delivery.md` 交付

### Step 4: 记录
- 修改记录写入 `_task_ids.jsonl`，标注 edit_type 和修改范围
- 修改后的产物按 `delivery_standard.md` 命名（可加 `_v2` 后缀区分版本）
- **修改溯源**：修改记录除 edit_type 外必须附三字段
  - `edit_reason`：用户原始指令原文（不改写、不概括）
  - `before_snapshot`：改前关键内容（原台词文本 / 原 Prompt 摘要）或被替换视频的文件路径
  - `after_snapshot`：改后对应内容 / 新产物路径
  - 用途**仅供回溯查证，不做自动回滚**（回滚需用户显式指令）

## 约束
- 修改仅针对用户明确要求的范围，不主动改动未提及的内容
- 脚本级修改必须重新过合规校验，不能假设原脚本的合规结论仍然有效
- 保留式修改（音频级/字幕级）不需要用户重新确认，但需告知修改结果
- 重做式修改（镜头级及以上）产出后需用户确认再交付
