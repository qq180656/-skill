# 交付子流程 (Workflow Delivery)

## 前置条件
- VERIFYING阶段全部通过
- 逐字稿（`_逐字稿.srt` + `_words.json`，ASR words 直出）、口播字幕SRT（由逐字稿派生）和警示语SRT已生成，均在 `{YYYY-MM-DD}/字幕/`
- 发音错误已修复或确认为可接受

## 依赖知识库
- `knowledge/templates/quality_control.md` — 出片自检清单+KEEP/CHANGE修改协议
- `knowledge/templates/batch_fission_playbook.md` — 批量裂变操作手册（多版本交付时的版本矩阵产物组装+共享镜头交付目录组织+按版本命名规范）
- `outputs/delivery_standard.md` — 交付物清单+目录结构+命名规范

## 执行步骤

### Step 1: 产物组装 (ASSEMBLE)
- 收集所有最终产物，按日期分层归档:

```
{项目名}/
├── _task_ids.jsonl              ← 根目录，跨日期汇总追加
├── _视频日志.csv                ← 根目录，跨日期汇总追加
├── _batch_log.txt               ← 根目录，批量执行日志（跨日期追加）
├── {YYYY-MM-DD}/
│   ├── 原始脚本.csv                    ← 当天脚本（序号/标题/正文/类型/字数）
│   ├── 成片/                            ← 正片产物（默认目录）
│   │   ├── {序号}_{名称}.mp4
│   │   └── {序号}_{名称}_full.mp4 (extend模式)
│   ├── 前贴/                            ← 前贴产物（与成片分开，同批混合时各自独立）
│   │   └── {序号}_{名称}.mp4
│   ├── 字幕/                            ← 口播字幕 + 逐字稿(SRT+JSON) + 警示语**同一目录**（不另建 `逐字稿/`）
│   │   ├── {序号}_{名称}_口播字幕.srt   ← 口播字幕（**由逐字稿派生**；成片/前贴各自独立子目录或前缀区分）
│   │   ├── {序号}_{名称}_逐字稿.srt     ← 逐字稿·人看版（每字一行，ASR words 直出，唯一源头）
│   │   ├── {序号}_{名称}_words.json     ← 逐字稿·程序版（每字 text/start/end）
│   │   ├── {序号}_{名称}_warn.srt      ← 警示语字幕（**仅成片**，前贴不生成）
│   │   └── {序号}_{名称}_发音错误.srt   ← 有错才生成
│   ├── 审核文档/                        ← 生成后（内嵌ASR逐字稿**文本版**+对照；逐字稿**文件**在 `字幕/`），成片/前贴分开
│   │   └── {序号}_{名称}.md
│   └── 脚本标注/                        ← 生成前（脚本+警示语确认），**仅成片**，前贴不生成
│       └── {序号}_{名称}.md
├── {YYYY-MM-DD}/
│   ├── 原始脚本.csv
│   ├── 成片/
│   ├── 字幕/
│   ├── 审核文档/
│   └── 脚本标注/
└── _发音修复/                           ← 修复版（有错才有，不按日期分）
    └── {序号}_{名称}_fixed.mp4
```

- 注意: 字幕不烧入视频,作为独立SRT文件交付
- _task_ids.jsonl 和 _视频日志.csv 每次追加写入，不按日期拆分
- **批量裂变交付**：多版本裂变场景下，参考 `batch_fission_playbook.md` 的按版本交付规范——共享镜头产物只存一份（各版本复用同一文件路径），各版本独有镜头按版本矩阵命名归档，版本间差异项在 `_batch_log.txt` 中注明
- **生成 `{YYYY-MM-DD}/原始脚本.csv`**（交付必须产物）：从本批 `parsed_script.json`/`atomic_scripts.json` 与原始脚本导出，字段 序号/标题/正文(含括号警示语)/类型/字数(去括号)；此产物由本步骤负责产出（此前无任何步骤生产，会导致 QC 失败）

#### 前贴/成片产物分目录
- **成片** 放 `成片/`，**前贴** 放 `前贴/`，二者物理隔离，不得混放同一目录
- 同一批既出成片又出前贴（混合批）：各自独立目录，`字幕/`、`审核文档/`、`脚本标注/` 也按成片/前贴分别归档
- **前贴目录不生成** 警示语SRT（`_warn.srt`）和 `脚本标注/` 文档；QC（Step 2）对前贴跳过「警示语完整」「脚本标注存在」两项检查，缺失不判失败

#### 同名文件覆盖策略
- 首次生成：正常写入目标路径
- 重新生成（同序号同名）：**新文件覆盖**目标路径，旧文件移入同级 `_历史版本/` 并加时间戳后缀，如 `01_好医保_v1_20260910.mp4`
- `_task_ids.jsonl` / `_视频日志.csv`：**只追加不覆盖**，每条记录附 `batch_id`（格式见 Step 1.5），便于按批次回溯

### Step 1.5: 批量日志生成 (BATCH_LOG)
- 生成 `_batch_log.txt`，记录本次批量生成的所有视频信息：
  - 文件名、序号、时长、模型、生成时间、状态（成功/失败/跳过）
  - 失败的视频记录失败原因和异常码
- 存放位置：`{项目名}/_batch_log.txt`（根目录，跨日期追加）
- 用途：便于追溯和统计本次批量生成的结果
- **跨日期去重**：每批开头写入一行分隔标记
  ```
  === BATCH START: {batch_id} {timestamp} ===
  ```
  - `batch_id` 格式 `B{YYYYMMDD}_{序号}`，如 `B20260910_01`（同日第二批为 `B20260910_02`）
  - 中断后重启：读取日志中**最后一条 BATCH START** 之后的记录，若已存在相同 `task_id`，该条**跳过**不重跑，避免跨日期重复扣费/重复出片

### Step 2: 质检 (QC_CHECK)
检查项（按顺序，前置项失败则短路）:
- **视频可播放性检查（首道闸）**：用 `ffprobe` 验证每个 mp4 可解析——必须同时存在视频流 + 音频流、`duration` 非 0、无损坏/解码报错（ffprobe 退出码为 0 且 stderr 无 error）
  - **前贴额外检查**：音频流应为纯 BGM/环境音，**不得混入台词人声**（ASR 识别字数显著 > 0 即判混入）
  - 不可播放 → 直接标 QC 失败，**不进入后续任何校验项**
- 文件完整性: 所有必需产物都存在
- 命名规范: 符合 outputs/delivery_standard.md
- 格式正确: mp4为H.264编码, srt为UTF-8（编码细则见下）
- **SRT 编码规范**：必须为 UTF-8 **without BOM**；检测到 BOM 头（`EF BB BF`）自动去除后重写；换行符统一 **LF (`\n`)**，不用 CRLF（`\r\n`）
- 时长一致: 视频时长应≈"脚本预估时长 + 2秒缓冲"（生成目标本就含 +2s，见 wf_generation Step1 / config_matrix）；判定按 `|实际时长 − (预估时长 + 2s)| ≤ 1秒`，**不要用"与预估时长误差<2秒"**（会因缓冲被系统性误判为不合格）
  - **+2秒缓冲来源说明**：+2s 来自 wf_generation Step1 的**尾帧收束预留**（结尾画面稳定停留），并非估算误差冗余。因此 QC 比对基准 = **预估时长 + 2s**（而非预估时长本身），实际与基准偏差 ±1s 内为正常
- 字幕对齐: SRT时间轴与视频音轨匹配
- 警示语完整: 成片的所有触发句都有对应警示语；**前贴跳过此项**（前贴不挂警示语）；用户在 E007 已确认跳过的触发句，读取合规报告/快照的跳过记录并豁免，不重复报错
- 无 AI 生成的伪水印/假logo（**合规追踪水印除外**——追踪水印为主动嵌入，见 `outputs/暗水印编号追踪规范.md`，不得判为"残留水印"）
- 若质检失败 -> WAITING_USER(展示问题让用户决策)

### Step 3: 用户确认
- 展示最终产物清单供用户确认
- 展示质检报告
- 用户确认通过 -> 进入归档
- 用户要求修改 -> 回退到对应阶段
- **回退精度分级**（按问题类型定位最小回退点，禁止一刀切回脚本级重做）：
  | 问题类型 | 回退目标 | 是否重生视频 |
  |----------|----------|-------------|
  | 字幕时间轴偏移/错位 | 回**字幕生成**重新对齐 | 否（只重生成 SRT） |
  | 画质/内容问题（崩坏、镜头不符） | 回 `wf_generation.md` **重做该镜头** | 是（仅该镜头） |
  | 警示语遗漏/未挂载 | 回 **COMPLIANCE_CHECK** 补挂 | 否（只补 SRT/叠字） |
  | 整体脚本修改（换措辞/换利益点） | 回**脚本撰写**（路径 B Step3 / 路径 A Step1） | 是（受影响镜头或全片） |

### Step 4: 归档 (ARCHIVE)
- 将最终产物移至交付目录
- 清理中间临时文件(保留ASR逐字稿和执行日志)
- **中间文件清理白名单**（严格按名单，不得扩大删除范围）：
  - **保留**：ASR逐字稿（`字幕/{序号}_{名称}_逐字稿.srt` + `{序号}_{名称}_words.json`）、口播字幕SRT、`_batch_log.txt`、`_视频日志.csv`、`_task_ids.jsonl`、`审核文档/` 文档、`脚本标注/` 文档、`creative_design.md`、`storyboard.md`
  - **删除**：`parsed_script.json`、`atomic_scripts.json`、`shot_*.mp4` 单镜头临时片段（合成后的 output 成片**保留**）、合成过程临时文件（concat list、中间 ts/分段等）
  - **清理前必须先输出待删清单给用户确认，禁止静默删除**
- 生成交付摘要: 项目名/脚本数/视频数/总时长/质检状态
- 状态机进入 DONE
