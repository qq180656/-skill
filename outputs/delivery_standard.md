# 第五层：交付规范

## 交付物清单

| 文件 | 说明 | 位置 | 必须 |
|------|------|------|:----:|
| `原始脚本.csv` | 当天脚本（序号/标题/正文/类型/字数） | 日期目录下 | ✅ 必须 |
| `{序号}_{名称}.mp4` | 裸视频（无字幕） | 成片/ | ✅ 必须 |
| `{序号}_{名称}_口播字幕.srt` | 口播字幕SRT（≤13字/行，LLM断句，观众看/烧入用） | 字幕/ | ✅ 必须 |
| `{序号}_{名称}_逐字稿.srt` | 逐字稿SRT（每字一行+精确时间戳，审核/剪辑/对口型用） | 字幕/ | ✅ 必须 |
| `{序号}_{名称}_words.json` | 逐字稿JSON（程序读取用，每字start/end/text） | 字幕/ | ✅ 必须 |
| `{序号}_{名称}_warn.srt` | 警示语SRT（成片才有） | 字幕/ | 成片必须 |
| `{序号}_{名称}_发音错误.srt` | 发音问题标注 | 字幕/ | 有错才生成 |
| `{序号}_{名称}.md`（脚本标注） | 脚本正文+警示语对应确认（生成前） | 脚本标注/ | 成片必须 |
| `{序号}_{名称}.md`（审核文档） | ASR逐字稿（**加标点的可读文本版**）+触发句↓警示语（生成后） | 审核文档/ | ✅ 必须 |
| `{序号}_{名称}_fixed.mp4` | 发音修复后视频 | _发音修复/ | 有错才生成 |
| `_task_ids.jsonl` | 任务追溯（task_id + prompt + 响应） | 根目录 | ✅ 必须 |
| `_视频日志.csv` | 视频生成日志（**完整字段以 `暗水印编号追踪规范.md` §4.1 为准**：序号/项目/水印编号/名称/类型/版本/时长/提交完成时间/状态/task_id/本地文件/费用/模型） | 根目录 | ✅ 必须 |
| `_batch_log.txt` | 批量执行日志 | 根目录 | ✅ 必须 |
| `成片_带水印/{序号}_{名称}.mp4` | 前10s右下角追踪编号水印版（见 `暗水印编号追踪规范.md`，由 WATERMARK_EMBED 产出） | 成片_带水印/ | 投放必须 |
| `参考图/character_{脚本号}_{角色名}.jpg` | 角色四视图设定稿（Seedream 5.0生成，16:9横版） | 参考图/ | 用了image2video时必须 |
| `参考图/scene_{脚本号}_{场景名}.jpg` | 场景空镜参考图（Seedream 5.0生成） | 参考图/ | 按需 |
| `_参考图索引.jsonl` | 参考图追溯（URL/本地路径/生成参数/复用记录），跨日期追加 | 根目录 | 用了生图时必须 |

> **逐字稿 ↔ 口播字幕 = 源头 ↔ 派生（唯一源头原则）**
> - `_逐字稿.srt` + `_words.json`：ASR words **直出**的逐字原始数据（不经 LLM，不做任何断句/合并/纠错），是字幕链路**唯一源头**。SRT 给人看/播放器加载，JSON 给程序读。
> - `_口播字幕.srt`：**由逐字稿派生** —— `逐字稿 → LLM 语义断句 → 口播字幕`，时间戳取逐字稿词时间戳。**不是**从 ASR 独立生成的第二份产物。
> - 三者同放 `字幕/`，**不另建 `逐字稿/` 子目录**。格式/命名/产出规范见 `knowledge/video_parameters/asr_processing.md` 第10.5章。

### 文件命名规范

**统一命名格式（以后新批次必须遵守）**：`{产品缩写}-{YYMMDD}脚本{N}-{版本}.mp4`

示例：
- `HYB-260908脚本1-v1.mp4`（好医保中老年，260908批，脚本1，版本v1）
- `HYB-260908脚本1-四川话-v2.mp4`（四川话版本）
- `MZX-260903脚本5-v1.mp4`（门诊险前贴）

| 字段 | 说明 |
|------|------|
| 产品缩写 | HYB/MZX/CQB（同暗水印编号缩写表） |
| YYMMDD | 脚本批次日期（非生成日期） |
| 脚本N | 脚本序号 |
| 版本 | v1/v2/v3/v4（画面变体），方言标记加在版本前（如"四川话-v1"） |

> **已出片的文件名不改**（改了台账/飞书/水印编号全要联动）。历史批次命名不统一是事实，接受现状。

### 前贴 vs 成片交付物差异

| 交付物 | 前贴 | 成片 |
|--------|------|------|
| 警示语SRT (`_warn.srt`) | ❌ 不生成 | ✅ 必须 |
| 脚本标注文档 (`脚本标注/`) | ❌ 不生成（目录可留空） | ✅ 必须 |
| 审核文档 (`审核文档/`) | ✅ 必须（仅 ASR 逐字稿 + 原始脚本，无警示语对应表） | ✅ 必须（含触发句↓警示语对应表） |
| 压底/末尾字幕 | 按需（产品专属规则明确要求时） | 按需（产品专属规则明确要求时） |

## 两份文档区别

| 文档 | 目录 | 生成时机 | 内容 | 用途 |
|------|------|----------|------|------|
| 脚本标注 | 脚本标注/ | 视频生成**前** | 原始脚本正文 + 每句触发句↓完整警示语 + 三层校验结果 | 确认警示语挂对了再开跑 |
| 审核文档 | 审核文档/ | 视频生成**后** | ASR实际逐字稿(带标点·文本版) + 触发句↓警示语 + 原始脚本 | 确认视频念的跟脚本一致 |

**硬约束**：两份文档中的警示语必须显示完整内容，禁止用省略号(...)截断。

> 审核文档里内嵌的是**加标点的可读文本版**逐字稿（给人核对）；交付的逐字稿**文件**（`字幕/{序号}_{名称}_逐字稿.srt` + `_words.json`）保持 ASR 原始粒度：每字一条、不加标点、不做同音纠错。二者同源于同一份 ASR words，不要各跑一次。

## 审核文档格式

```markdown
# {产品名}脚本文案 - 警示语标注版
## 脚本{序号}: {描述}

### ASR逐字稿（视频实际发音，已加标点）
{加标点后的ASR文本}

### 文案正文与警示语精准对应关系
{逐行列出触发句↓警示语对应表}

### 完整标注文案（可直接用于脚本）
{原始带括号脚本}
```

## 审核流程
1. 生成审核文档 → 人工确认每个触发句↓警示语对应正确
2. 确认通过 → 生成最终SRT
3. 发音检测 → 有错修复 → 无错直接交付

## 投放合规要素（五要素+压底四要素）

### 产品宣传素材必备五要素

| 要素 | 生成方式 | 说明 |
|------|---------|------|
| 保司名称 | AI生成（口播+字幕） | 口播中准确提及承保保险公司名称，字幕同步展示 |
| 蚂蚁保名称 | AI生成（口播+字幕） | 口播中准确提及"蚂蚁保代理销售"，字幕同步展示 |
| 蚂蚁保logo | 后期叠加 | AI视频生成工具无法生成准确logo，需后期剪辑时叠加；不得让AI生成logo（会生成假logo） |
| 产品名称 | AI生成（口播+字幕） | 口播中完整、准确提及产品全称，字幕同步展示 |
| 每帧压底文案 | AI生成（字幕SRT） | 按下方压底四要素生成压底字幕SRT文件，后期叠加到视频 |

> 规则明细表为投放附件，由运营/投放团队提供，不属于AI视频生产交付物。

### 压底文案四要素（必须包含）

压底文案（每帧底部统一展示）必须包含以下四要素：

1. **广告创意声明**："本视频内容属广告创意"
2. **条款阅读提示**："保险产品详情请见投保须知及保险条款"
3. **承保+代理销售**："本产品由【XX保险公司】承保，蚂蚁保代理销售"
4. **费率提示**（提及保费时必须有）："具体费率及保险金额以实际投保为准"

> 抖音信息流渠道：压底需另加四要素【保费、保额、免赔额、赔付比例】，以各产品专属投放注意事项.md 为准。

### 压底字幕生成要求

- 生成独立的压底字幕SRT文件（`{序号}_{名称}_压底.srt`），时间轴覆盖全片
- 字体大小适中，不遮挡口播字幕和关键画面
- 位置固定在画面底部，不随镜头变化
- 前贴如不涉及利益点，压底可简化为广告创意声明+承保代理销售；成片必须包含完整四要素

## 交付检查清单
- [ ] 视频数量正确（和脚本条数一致）
- [ ] 每条视频有对应字幕文件（口播字幕SRT + **逐字稿SRT + words.json** + 警示语SRT，均在 `字幕/`）
- [ ] 逐字稿为 ASR words 直出（每字一条、无标点、无纠错），口播字幕SRT 由它派生
- [ ] 警示语SRT和审核文档一致
- [ ] 发音错误已修复或标注
- [ ] _task_ids.jsonl记录完整
- [ ] 原始脚本备份完整
- [ ] 必加提示已在压底或末尾字幕中体现
- [ ] 无合规问题（禁用词/绝对词/误导表述）
