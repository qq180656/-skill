# 暗水印编号追踪规范

## 一、目的

解决视频投放后"命名变了、md5变了、无法溯源"的问题。通过在视频前10秒右下角嵌入半透明编号水印，建立"编号 ↔ 视频链接 ↔ 费用 ↔ 投放数据"的映射关系，实现全链路追踪。

---

## 二、编号规则

### 2.1 编号格式

```
{项目缩写}{产品ID}-{YYMMDD}-{3位序号}
```

示例：`HYB52973-260902-001`

| 字段 | 说明 | 示例 |
|------|------|------|
| 项目缩写 | 项目名称拼音首字母，3位 | HYB（好医保） |
| 产品ID | 产品编号，**区分同缩写下不同产品**（好医保有 52973/52978/45750/52975，仅用 HYB 会撞号） | 52973 |
| 日期 | 批次生成日期，**YYMMDD**（含年份，防跨年撞号） | 260902 |
| 序号 | 3位数字，从001开始 | 001 |

### 2.2 项目缩写对照表

| 项目名称 | 缩写 |
|----------|------|
| 好医保中老年 | HYB |
| 长钱保 | CQB |
| 门诊险 | MZX |

（新增项目时在此表追加缩写）

> ⚠️ 好医保系多产品（52973 中老年 / 52978 体验版 / 45750 少儿 / 52975 旗舰版）共用缩写 HYB，**必须靠产品ID区分**（编号中缩写与产品ID连写，如 `HYB52973` / `HYB45750`），否则不同产品撞号，违背"唯一追踪"目的。

### 2.3 序号分配原则

- 每个视频唯一编号，不重复
- 按CSV中的顺序依次分配（001, 002, 003...）
- 重跑/补跑的视频使用新编号，不复用旧编号
- 编号一旦分配，永久保留，即使视频删除也不回收

## 三、水印嵌入规范

### 3.1 盲水印（主方案，肉眼不可见）

使用 `scripts/blind_watermark_video.py` 的 `embed_watermark_video`，基于 DWT+DCT+SVD 频域嵌入，肉眼完全不可见，可用 `verify_watermark_video` 提取校验。

| 参数 | 值 | 说明 |
|------|-----|------|
| 算法 | blind_watermark (DWT+DCT+SVD) | guofei 实现，4×4分块，**d1=10 d2=5**（嵌入强度从默认36/20降到10/5，最大像素差5，PSNR≈47.5dB，肉眼无感） |
| 内容 | 水印编号 | 如 MZX36866-260903-001 |
| 抽样窗口 | window=100帧（高码率片源）/ **window=50帧（低码率片源，推荐AI生成视频用）**, per_window=1帧 | 每窗口首尾帧必选。低码率片源用50帧窗口把密度提到约4%（48帧/1150帧），弥补重编码偶发丢帧导致的抽帧网格错位漏检 |
| 编码码率 | **按源码率分流（见下方§3.1.1）**：源码率≥3Mbps → CBR=源码率×1.2；**源码率<3Mbps（AI生成低码率片源，如 Seedance 720p≈1.5Mbps）→ 固定 CBR 4M（bufsize 8M）** | CBR×1.2 在低码率片源上仅约1.8M，会把d1=10弱水印压没（实测0命中）；固定4M实测稳定命中 |
| preset | slow | 编码质量优先 |
| 关键帧 | 水印帧强制为I帧 | P/B帧运动预测会破坏水印 |
| 输出 | 全片统一重编码 | 不切割拼接，避免编码参数不一致导致拼接点卡顿 |

**实测验证（门诊险02号视频）：**
- 原始 6.4Mbps → 盲水印 6.7Mbps（码率匹配，画质无感）
- 529帧嵌12帧，校验检查300帧命中9帧（75%命中率），编号完整提取 ✅
- d1=36（默认）→ 马赛克块状噪声可见；d1=10 → 肉眼完全无感

#### 3.1.1 低码率片源必须提高重编码码率（2026-09 实测，踩坑）

**问题**：上面 CBR×1.2 + window=100 的参数只在 **高码率片源（≥3Mbps）** 上验证过。AI 生成视频（豆包 Seedance 2.5 产出的 720p/24fps）源码率常**低至 1.5Mbps**，此时 CBR×1.2≈1.8M，d1=10 弱水印被 x264 色度子采样(yuv420p)+量化直接压没——好医保中老年0907剧情批次10条**首次嵌入 verify 全部 0 命中**。

**对照实验结论（720p真实运动画面，固定水印帧为I帧）**：

| 强度 d1/d2 | 像素格式 | 重编码码率 | 水印存活 |
|-----------|---------|-----------|---------|
| 10/5（规范默认） | yuv420p | 1.8M（=1.5M×1.2） | ❌ 0命中 |
| 36/20 | yuv420p | 1.8M / crf18(实际2.2M) | ❌ 仅1-2/600 |
| 36/20 | yuv444p | 1.8M | ✅（但yuv444投放兼容性差，不用） |
| **10/5（规范默认）** | yuv420p | **固定4M** | ✅ **12-20/300，全部水印边界帧稳定存活** |
| 10/5 | yuv420p | 固定6M | ✅ 25/600（文件3.5x，过大） |

**关键认知**：决定水印存活的是**重编码码率**，不是强度。d1=10 肉眼最无感，在4M码率下已足够，无需升到d36。水印帧仅闪现 1/24 秒，即使d36单帧有轻微块状噪声，播放中也察觉不到。

**定稿参数（AI生成低码率片源）**：

```python
# 强度不变（d1=10/d2=5 在 blind_watermark_util.py 内硬编码），只改码率与窗口：
# 分段编码用固定 4M CBR（bufsize 8M）替代"源码率×1.2"，window=50
cmd = [FFMPEG, "-y", "-framerate", fps, "-start_number", str(start), "-i", pattern,
       "-frames:v", str(end-start+1),
       "-c:v", "libx264", "-preset", "slow",
       "-b:v", "4M", "-maxrate", "4M", "-bufsize", "8M",
       "-pix_fmt", "yuv420p",
       "-force_key_frames", f"expr:{keyframe_expr}", "-an", seg_path]
embed_watermark_video(src, dst, text=wm_id, window=50, per_window=1)
```

- 10条剧情片实测：源9-19MB → 水印版21-35MB（约2-2.5x），verify 命中12-20/300（标准仅需 matched>0）
- 判定门槛：**先 ffprobe 看源码率，≥3Mbps 用 CBR×1.2 + window=100；<3Mbps 用固定4M + window=50**

**另两个工程坑（同批踩中）**：
1. `blind_watermark_video.py` 用 `FFPROBE = FFMPEG.replace("ffmpeg","ffprobe")` 推导探针路径。若 ffmpeg 在 `C:\ffmpeg\bin\`，替换会把目录名误改成 `C:\ffprobe\bin\`（不存在）→ WinError 2。须设环境变量 `FFMPEG_PATH` 指向 ffmpeg.exe 与 ffprobe.exe **同目录**的安装（如 build_video/tools/）。
2. 抽全帧PNG（每条2-3GB临时目录）连续处理会触发 numpy/opencv **C层硬崩溃**（进程退出无Python traceback）。必须**每条视频一个独立子进程隔离**处理，崩溃只影响单条。参考实现：`精华部分/大语言模型/scripts/_embed_blind_wm_0907.py`（`--one`单条 + 驱动模式逐条 subprocess.run）。

**嵌入命令（Python）：**

```python
from scripts.blind_watermark_video import embed_watermark_video

embed_watermark_video("成片/01_xxx.mp4", "成片_带水印/01_xxx.mp4", text="MZX36866-260903-001")
```

**校验命令：**

```python
from scripts.blind_watermark_video import verify_watermark_video

result = verify_watermark_video("成片_带水印/01_xxx.mp4", expected_text="MZX36866-260903-001")
# result = {'total_frames': 529, 'checked': 300, 'matched': 9, 'matched_frames': [0, 100, ...]}
# matched > 0 即确认含此编号水印
```

**依赖：** `pip install blind-watermark opencv-python numpy`，ffmpeg（环境变量或 FFMPEG_PATH）

### 3.2 drawtext 追踪水印（可选，人工快速辨认用）

如需人眼快速辨认编号（不想播放→截帧→跑校验脚本），可额外叠加 ffmpeg drawtext 半透明水印。**不作为主方案**（浅色背景可见）。

| 参数 | 值 | 说明 |
|------|-----|------|
| 位置 | 右下角 | x=w-tw-30, y=h-th-30（距边缘30px） |
| 显示时长 | 前10秒 | enable='between(t,0,10)' |
| 字号 | 24px | 720p视频适用 |
| 颜色 | 白色半透明 | fontcolor=white@0.15（降低可见度） |
| 描边 | 黑色半透明 | borderw=1, bordercolor=black@0.15 |

```bash
ffmpeg -y -i input.mp4 \
  -vf "drawtext=fontfile='C\:/Windows/Fonts/arial.ttf':text='MZX36866-260903-001':fontsize=24:fontcolor=white@0.15:borderw=1:bordercolor=black@0.15:x=w-tw-30:y=h-th-30:enable='between(t,0,10)'" \
  -c:v libx264 -preset fast -crf 20 -c:a aac -b:a 128k -movflags +faststart output.mp4
```

### 3.3 输出目录

- 源视频：`{项目目录}/{日期}/成片/`
- 带水印视频：`{项目目录}/{日期}/成片_带水印/`
- 不覆盖原文件，带水印版本单独存放

### 4.2 维护流程

1. **生成时**：批量生成脚本自动分配编号，记录到CSV
2. **加水印时**：根据CSV中的编号给对应视频嵌入水印
3. **投放时**：记录投放平台、投放账号、投放时间，与水印编号关联
4. **追踪时**：从视频中读取右下角编号 → 查CSV → 获取视频链接、费用、脚本信息

## 六、与视频消耗追踪的关联

### 6.1 追踪链路

```
视频投放 → 读取水印编号 → 查CSV映射表 → 获取：
  ├── 视频链接（task_id可追溯到原始生成任务）
  ├── 生成费用（人民币，P1+P2）
  ├── 脚本信息（标题、类型、版本、字数）
  └── 生成时间（提交/完成时间）
```

### 6.2 费用核算

- CSV中的"费用(元)"列是从豆包API `task_status` 接口的 `cost_cny` 字段实时获取的
- 双段视频费用 = P1(text2video) + P2(reference2video)
- 单段视频费用 = P1(text2video)
- 费用明细记录在"备注"列，如 `费用明细:P1¥51.20+P2¥48.65`

### 6.3 投放数据回填（建议）

后续可在CSV中增加以下列，用于投放效果追踪：
- 投放平台（抖音/快手/视频号）
- 投放账号
- 投放时间
- 消耗金额（平台侧）
- 播放量/互动量/转化量

## 七、批量生成脚本集成

### 7.1 现有脚本

- `scripts/_run_yxh_batch.py`：营销号批量生成
- `scripts/_run_jq_batch.py`：剧情批量生成

> ⚠️ 上述脚本为**外部实现**（位于批量工具 / 大语言模型的 scripts 目录），**不在本『AI视频生产规范』仓库内**。本规范只定义编号/嵌入/映射标准；实际嵌入由 DELIVERING 阶段的 `WATERMARK_EMBED` 任务（见 `core/task_registry.md`）调用外部脚本完成。

### 7.2 集成点

1. **编号分配**：脚本启动时读取CSV，获取最大序号，新视频依次分配
2. **费用记录**：`poll` 函数已修改为返回 `(video_url, cost_cny)`，`log_video` 时记录费用
3. **水印嵌入**：视频生成完成后，自动调用水印嵌入函数，输出到 `成片_带水印/` 目录
4. **CSV记录**：所有信息（编号、费用、文件路径）统一记录到 `_视频日志.csv`

### 7.3 使用方式

```bash
# 营销号批量生成（自动加水印+分配编号+记录费用）
python scripts/_run_yxh_batch.py

# 剧情批量生成
python scripts/_run_jq_batch.py

# 单独给已有视频加水印
python _embed_watermark.py --test   # 测试1个
python _embed_watermark.py           # 批量处理
```

## 八、注意事项

1. **水印只在前10秒显示**：如果视频被裁剪掉前10秒，水印会丢失。重要投放建议全帧嵌入（待开发）。
2. **编号不可修改**：编号一旦分配并嵌入视频，永久不变，CSV中也不可修改。
3. **备份原文件**：带水印版本单独存放，不覆盖原文件。
4. **费用实时获取**：费用从API实时获取，不是估算值，确保准确。
5. **中文文件名**：ffmpeg处理中文文件名时需确保编码正确（Python脚本用UTF-8）。
