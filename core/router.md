# Agent 路由逻辑 (Router)

## 1. 入口信号识别

Agent 接收到用户输入后，执行以下判定流程，将输入归入唯一路径。

### 判定算法

```
INPUT: user_message
OUTPUT: route_path ∈ {A, B, C, EDIT, ERROR}

STEP 0: 优先级判定（当输入同时含脚本和Brief时）
  CONDITION: 用户消息既包含脚本片段（>20字的结构化口播），又包含需求说明文字
  SUB-JUDGE: 判断脚本片段完整性 + 用户意图
    - **新创作意图优先**：若需求明确要"新做/再做N条/别重复已有/换新场景钩子"，则所给脚本是**风格/合规参考样本**（非生产对象）→ route_path = B（参考样本作为 CREATIVE_DESIGN 的风格输入，绝不把旧脚本原样再生产一遍）
    - 完整脚本（有开头有结尾、覆盖全片口播、>50字）且无新创作意图 → 需求说明仅作为元信息（产品名/类型/数量），按 STEP 1 走路径A
    - 部分片段（仅覆盖某一段/某一句、无完整结构）→ route_path = C（混合输入）

STEP 1: 检查是否包含完整脚本
  CONDITION: 用户消息中包含逐段画面描述、分镜表、带角色台词的完整剧本，
             或含时间轴的逐段口播文案（>50字的结构化文本）
  MATCH → route_path = A

STEP 2: 检查是否为项目/需求指令
  CONDITION: 用户消息为简短指令，如"我要好医保中老年的前贴"或"做好医保门诊险的成片"
  MATCH → route_path = B

STEP 3: 检查是否为修改/追加指令
  CONDITION: 用户要求修改已有产物（换镜头/改台词/调风格/改字幕/换BGM）——产物可在上下文中，**也可仅存在于磁盘**（`_task_ids.jsonl`/交付目录，如"昨天那条视频把第二句字幕改一下"）；agent 应先按 wf_edit.md Step1 从磁盘定位，**不因产物不在上下文就误判为新建**。带完整新脚本的"脚本级"修改仍属 EDIT，不要因含脚本就抢到 STEP 1
  MATCH → route_path = EDIT (走 wf_edit.md；状态机见 state_machine.md §5 的 EDIT 回边)

STEP 4: 兜底
  DEFAULT → route_path = B (按 Brief 驱动处理，先补齐信息再创作)
```

## 2. 路径定义

### 路径 A: 完整脚本直入 (entry_direct_script.md)

**适用场景**: 用户直接粘贴或上传了包含口播文案的完整脚本（可能含括号警示语，也可能不含）。

**Agent 行为**:
1. 不重新创作脚本，直接对现有脚本进行**原子化拆解**（SCRIPT_PARSE → SCRIPT_ATOMIZE）。
2. 执行 TTS 发音优化（断句、空格注入、删除级词删除）。
3. 执行合规校验（COMPLIANCE_CHECK：禁用词扫描、警示语挂载）。
4. 进入分镜规划（STORYBOARD）——⛔ 必经状态，禁止跳过直接进入视频生成。
5. 生成前最终确认（READY 门），用户确认后进入视频生成。

**关键约束**:
- 禁止重写、精简或合并用户脚本中的台词。
- 警示语如用户脚本中已包含，直接提取；如未包含，根据 `knowledge/compliance/` 中的规则自动补挂。
- 用户说"前贴" → 每条脚本时长目标 15-30s（单段,不走 extend）；说"成片" → 根据内容量弹性定时长。
- 前贴/成片类型判定见 §5 统一规则。

### 路径 B: Brief/需求驱动 (entry_brief_only.md)

**适用场景**: 用户只给了项目名和类型（如"我要好医保中老年的前贴"），没有脚本。

**Agent 行为**:
1. 读取 `knowledge/compliance/` 中的产品合规规则。
2. 读取 `knowledge/video_parameters/` 中的语速、时长、模型参数。
3. 执行创意设计（CREATIVE_DESIGN）——产出 creative_design.md 并获用户确认（前贴和成片都必做）。
4. 基于创意方案撰写脚本（含警示语标注）。
5. 对脚本进行**原子化拆解**（SCRIPT_PARSE → SCRIPT_ATOMIZE）+ TTS 优化 + 合规校验（COMPLIANCE_CHECK）。
6. 进入分镜规划（STORYBOARD）。
7. 生成前最终确认（READY 门），用户确认后进入视频生成。

**关键约束**:
- 撰写脚本前必须确认前贴 vs 成片（时长不同），判定见 §5 统一规则。
- 必须过三层合规规则叠加。
- 脚本产出后需用户确认再进入生成阶段。
- CREATIVE_DESIGN 是路径B的必经状态（state_machine.md §5），禁止跳过。

### 路径 C: 混合输入 (entry_mixed.md)

**适用场景**: 用户同时提供了部分脚本片段和部分需求说明，如"做好医保中老年的成片，开头要讲0免赔，中间讲报销比例，最后加一句投保链接。脚本参考以下片段：好医保中老年长期医疗..."

**Agent 行为**:
1. 从脚本片段中提取已确定的内容（口播文本、可能的警示语）。
2. 从需求说明中提取未覆盖的部分（缺失的场景、台词、情绪）。
3. 合并两部分信息，补齐缺失内容，生成完整脚本。
4. 进入路径A的原子化拆解流程（SCRIPT_PARSE → SCRIPT_ATOMIZE → COMPLIANCE_CHECK）。
5. 进入分镜规划（STORYBOARD）——⛔ 必经状态，禁止跳过直接进入视频生成。
6. 生成前最终确认（READY 门），用户确认后进入视频生成。

**关键约束**:
- 用户已提供的脚本片段不修改，仅补齐缺失部分。
- 补齐内容需过三层合规规则叠加。
- 合并后的完整脚本需用户确认再进入生成阶段。

### 路径 EDIT: 修改指令 (wf_edit.md)

**适用场景**: 用户对已有产物提出修改（换镜头/改台词/调风格/加字幕/换BGM等）。

**Agent 行为**:
- 先按 `wf_edit.md` 的修改类型判定表，确定修改属于音频级/字幕级/镜头级/台词级/脚本级
- 音频级/字幕级（保留式修改）→ 直接执行，不需重新生成视频
- 镜头级/台词级 → 仅重做受影响部分，KEEP 的镜头复用原文件
- 脚本级（重做式修改，如换题材/重写脚本）→ 回到路径 A 或 B 重走全链路
- 所有修改完成后必须重跑受影响的校验项

## 3. 分流后公共执行链

无论路径 A、B 还是 C，脚本就绪后都进入以下公共链路：

```
脚本就绪 (Atomic Scripts)
    │
    ▼
┌─────────────────────────────────────┐
│ STORYBOARD → ASSET_PREP → READY → GENERATING → VERIFYING → DELIVERING → DONE │
└─────────────────────────────────────┘
```

具体执行逻辑见 `workflows/` 下各子流程文档。

> ⚠️ 上图为"脚本就绪（PLANNING 产出 Atomic Scripts）后"的分流速览。**完整主干状态序列（INPUT_PARSE → CREATIVE_DESIGN → PLANNING → STORYBOARD → ASSET_PREP → READY → GENERATING → VERIFYING → DELIVERING → DONE）与所有状态转移，以 `core/state_machine.md` 为唯一权威**；README 与本文的流程图仅作导航，如有出入以状态机为准。

## 4. 用户交互规范 — 平台适配

### 问卷效率约束
- **禁止连续超过2轮追问**：所有信息缺口合并到同一次问卷，不分多次反复询问
- **已确认的维度不再追问**：风格词已有 → 问卷不含风格；比例已有 → 不含比例；时长已有 → 不含时长
- **不询问是否使用字幕**：默认不使用；用户明确要求时通过成片合成的字幕参数实现
- **不询问是否配BGM**：默认配乐（单段由视频模型自带，多段合成时统一生成）；用户明示不要或已提供音乐文件时不配
- **问卷标题简短**：标题和每个问题都是一句话短提问，不把方案摘要/多行清单/编号列表塞进问卷

### 下一步建议模板
完成关键步骤后，给出2-3个编号建议，默认推荐项标注"（推荐）"：

| 完成步骤 | 建议内容 |
|---------|---------|
| 创意方案定稿 | ①确认创意继续制作（推荐） ②修改剧本（附可调项：角色/结局/时长） ③调整角色/场景形象或配音音色 |
| 分镜规划定稿 | ①确认分镜开始生成（推荐） ②修改特定镜头 ③调整整体节奏/时长 |
| 视频生成完成 | ①修改某个镜头重新生成 ②调整风格/氛围重新制作 ③基于此继续做续集 |
| 成片交付完成 | ①满意则结束 ②修改画面/动作 ③换BGM/加字幕/超分等后处理 |

### 前贴/成片类型统一判定规则 (§5)

**判定逻辑（优先级从上到下）**：

1.  **用户明确指定**：用户提及"前贴"、"钩子"、"短片" $\rightarrow$ **前贴**；提及"成片"、"完整视频"、"宣传片" $\rightarrow$ **成片**。
2.  **利益点关键词扫描**（命中任一即为成片）：
    - `保费/价格/多少钱/几块/报销比例/赔付比例/免赔额/0免赔/续保/保证续保/带病投保/确诊即赔/住院医疗/门诊报销/报销额度/最高赔/保额`
3.  **未命中关键词** $\rightarrow$ **前贴**。
4.  **冲突/不确定** $\rightarrow$ **询问用户**。

**类型差异化规范**：

| 维度 | 前贴 (Pre-roll) | 成片 (Full Video) |
|------|--------------|-----------------|
| **核心目标** | 场景化引入/引出产品名 | 讲利益点/保障内容/保费/比例 |
| **时长目标** | 15-30s | 弹性时长（根据内容量） |
| **合规校验** | 三层全读，仅验禁用词 | 三层全读，包含警示语挂载校验 |
| **脚本标文** | 不生成（不涉及利益点） | **必须生成**（脚本标注文档） |
| **警示语** | 无需挂载 | 必须逐句挂载 |

### 确认门原则
- **必设的是花钱前门**：分镜确认 + 生成前最终确认（READY）
- 上游门按不确定性加：仅当引入的不确定性高、晚发现很贵时才加
- 任何路径不超过2道确认门
- **用户明确要求跳过确认**（"直接生成""马上开始做"等）→ 全部停顿门降级为简明说明、不停顿；硬约束缺口仍按问卷补齐
